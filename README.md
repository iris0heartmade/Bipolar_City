# BIPOLE · 双极城市纪事

基于现有设计稿的本地 Web 城市经营游戏，当前为 0.2.0 魔导工业风与 M1 经营版本。Python 后端维护经营状态，浏览器显示暮色等距城镇；黄铜仪表、术式纹样、建筑、魔导灯、树木与人物均由代码绘制。

作者：**iris0heartmade**。项目仓库：[iris0heartmade/Bipolar_City](https://github.com/iris0heartmade/Bipolar_City)。使用原仓库的 [MIT 许可证](LICENSE)。

## 1. 启动与试玩

需要 Python 3.11 或更新版本。首次使用建议在项目目录创建虚拟环境（通俗比喻：项目独立的工具箱）：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m backend.app
```

当前开发环境已经具备依赖，也可直接运行 `python -m backend.app`，或运行 `start.ps1`。浏览器打开 [本地游戏](http://127.0.0.1:8876)。必须通过后端打开，不能双击 HTML 文件。

端口被占用时，更改 `data/server.json`，或在 PowerShell 当前窗口运行：

```powershell
$env:BIPOLE_PORT = '8877'
python -m backend.app
```

试玩顺序：

1. 选择左侧联排住宅或工人公寓，并选择公共出租或建成待售；沿道路寻找入口可接通的空地。
2. 按 R 或底部旋转按钮调整方向。绿色表示可建、红色表示不合法、黄色小格表示入口。
3. 点击地图放免费蓝图，再确认施工；资金此时扣除。
4. 点击继续，服务端按日施工；或保持暂停，点击推进一个月。公共住宅竣工即开放容量；待售住宅按实际成交开放对应容量。
5. 查看经营面板的待售库存、成交房款与实际商户。商户按消费需求逐月入驻/退出，带来真实岗位。
6. 查看建筑产权、施工队列和财政账本，再保存。读取须确认替换未保存进度。

拖动地图平移，滚轮/加减按钮缩放，Esc 退出建造。手机选择建筑后会自动滚回地图。格子按钮显示空间约束，住房按钮显示住宅容量。

服务启动总是生成测试开局；不会自动读取存档。点击读取恢复已有城市。保存位置是 `saves/slot1.json`，上一份保留为 `slot1.bak`。新开局不会删除存档。关闭页面不会暂停服务端时间，请先暂停或关闭服务。

## 2. 已实现功能与边界

| 已实现 | 具体行为 |
|---|---|
| 已有城镇开局 | 固定河流、道路与桥，种子控制初始住宅选择 |
| 格子建设 | 整数格、多格占地、四向旋转、冲突/地形/道路入口校验 |
| 施工 | 免费蓝图 → 扣费批准 → 待施工 → 施工中 → 竣工；重复请求不重复扣费 |
| 住房经营 | 公共出租、建成待售、分户成交、混合/私人产权、待售资产与实际入住 |
| 商户经营 | 集市按消费需求渐进入驻/退出，实际商户提供岗位、地方税与场地租金 |
| 人口与财政 | 已开放容量与实际岗位约束迁入；税收、租金、售房与维护分别记账 |
| 时间 | 暂停、0.5×/1×/2×、手动推进一个月；模拟不依赖画面帧率 |
| 存读档 | 版本 2 校验、已知 0.1.0 存档迁移、原子保存和备份；恢复失败保留当前城市 |
| 游戏界面 | 魔导工业仪表、暮色地图、术式光纹、魔导灯、产权工具与经营面板；支持桌面/手机/平板 |

原型地图为可配置的 28×28 测试城，替代建议中的 64×64，以便初版完整呈现。市政厅为固定地标；可新建住宅、公寓、集市、工坊、花园。道路暂固定，不支持新建道路、拆除或升级已完成建筑。

新开局的已有住宅为私人持有。新建住宅由政府出资，可公共出租或分户出售。每户容量、指导单价、月度成交上限和居民资金均为测试配置；住户购买需要真实资金与需求，未售库存不能当收入。售出部分不再收公共房租，也不承担市政维护；已售产权不可收回。未售公共住宅转待售前必须保障现有居民仍有替代住房。

居民以合计资金池模拟，月收入来自简化经济，扣除税、公共房租与购房款；不模拟逐户工资或个体买卖合同。初始购房需求代表改善住房意愿，迁入增加需求。政府租金只能按实际入住收取，居民余款不足时按可支付额度结算；暂不模拟租金欠款。集市商户按居民消费需求营业，工坊仍提供基础工业岗位，不模拟完整产业链和库存。花园环境加成、银行/按揭、NPC 城市、科技、议会、人物养成与 20 年评分仍在后续阶段。魔导光纹和路灯当前属于视觉演出，不表示已实现魔力供能系统。

服务面向本地单玩家，不支持多用户隔离或公网认证。已知 0.1.0 原配置的版本 1 存档可迁移：保留原有时间、现金、账目、施工和市政住房产权，初始化原版未模拟的居民余款及商户字段；页面纪事会提示迁移。原文件只有主动保存时才更新，保存前保留备份。未知配置或损坏存档拒绝加载。核心不使用运行期随机数，未来随机事件须持久化随机状态。

调用顺序：Web 操作 → HTTP 命令入口 → 世界服务 → 建设/财政等系统 → 权威世界状态 → 页面快照。HTTP（通俗比喻：前后台传递办事单的通道）仅传递意图与数据，页面不能自行增加现金或人口。

前端和后端是组合关系，不使用多层继承。仅一个服务端模拟循环，所有读写和时间推进通过同一锁串行处理。暂停关闭时间更新但保留页面交互；普通命令不会清空部分日计时。存档成功校验后整体替换世界。

月度结算顺序：居民收入 → 商户调整 → 人口迁移 → 购房需求和成交 → 住宅入住分配 → 税费/租金/维护 → 月报。政府常规结余预测不包含不确定的售房收入；实际月报包含已成交房款。

## 4. 配置与扩展

| 文件 | 可调整内容 |
|---|---|
| `data/buildings.json` | 占地、入口、费用、施工、分户容量/单价、铺位/每商户岗位、维护 |
| `data/balance.json` | 初始资金、居民余款/收入、税率、租金、成交上限、商户进退、日历 |
| `data/templates/river_town.json` | 地图尺寸、河流、道路、地标与初始住宅候选位置 |
| `data/server.json` | 本地监听地址与端口 |
| `frontend/js/theme.js`、`frontend/css/magic.css` | 地图/建筑/界面视觉，不改变经济或存档配置指纹 |
| `data/legacy/v1_manifest.json` | 原版只读兼容清单；用于识别已知旧存档，不应手动修改 |

金额以整数分币存储，界面除以 100 显示银镑。改经营配置后存档配置校验会阻止混用旧数值。增加建筑定义后，还需在 `art.js` 提供对应绘图；改地图时必须保证候选住宅和地标可建。

现行路线采用 P00—P10：先完成校准配置与统一交易账本，再做六行业资金闭合、人口/消费、双路径住宅和空间经济，随后进入贷款、贸易、公共服务及长期系统。旧 M0/M1/M2 编号仅用于历史原型。扩展功能由统一调度器调用，不另开经济循环。

## 5. 验证与文档

```powershell
python -m pytest -q
```

真实浏览器检查需要额外工具，首次安装：

```powershell
python -m pip install -r requirements-dev.txt
python -m playwright install chromium
python -m scripts.browser_check
```

浏览器检查会启动独立服务、使用临时存档并在结束后关闭服务，不改变试玩城市。检查真实鼠标/键盘/触摸操作，以及 M1 成交、租金、商户和保存恢复；截图与结果写入 `artifacts/`。0.1.0 验收保留在 [初版记录](docs/04_验收记录/验收记录.md)，本轮见 [0.2.0 验收记录](docs/04_验收记录/验收记录-0.2.0.md)。
