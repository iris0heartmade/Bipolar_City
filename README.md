# BIPOLE · 双极城市纪事

魔导城市经营原型。当前使用同一套七行业经济状态驱动地图、行业经营页面与桌面实验室；按月决策和结算。

## 1. 启动

需要Python 3.11或以上，以及Tk桌面组件。首次安装依赖：

```powershell
python -m pip install -r requirements.txt
python -m backend.app
```

也可双击 `start.ps1`，浏览器打开 [城市地图](http://127.0.0.1:8876/)；[行业经营与市政政策](http://127.0.0.1:8876/industry)和地图共享同一个城市，切换页面不会重置月份。

启动总是新城市，不自动读取或覆盖旧存档。服务仅供本机单玩家使用。可通过`BIPOLE_PORT`更换端口、`BIPOLE_SAVE_DIR`指定独立存档目录。

## 2. 如何经营

1. 查看政府现金、就业、行业经营现金和住房，决定预算用途。
2. 选择建筑，在草地放置；完整占地不能重叠或占用道路，黄色入口必须接道路。按R旋转。
3. 点击合法地块，市政府真实付款给工业施工；下一次月结完工。未完工不增加岗位或住房。
4. 工坊和集市增加岗位上限、生产设施及原料需求；实际就业取决于资金、需求和供货。住宅增加住房，不增加农业岗位。
5. 推进一个月，查看真实工资、销售、财政、人员流向、维护欠款和政策结果。
6. 在行业页面可发放补贴、雇佣公务员、发失业救济、限招、限裁及退还已缴行业税。持续政策从下一次结算开始，N月恰好覆盖N次月结；限裁不保证企业有钱足额发薪。
7. 保存后可以读取并继续同一条经营路径。存档保留施工、建筑能力、政策、欠薪及逐月历史。

新增公务员需要当场支付预付工资，并形成持续岗位计划，后续月份仍承担工资。补贴和救济有真实付款方；退税不能超过已缴未退税额或国库可支付余额。不能反复执行同一个请求来重复领取或建造。

市政采购的原料归市政持有，企业实际领用这批原料时向市政付款，回收采购周转资金；原有外部市场库存仍向外部支付。贸易支持金是单独的现金支持，不能当作原料采购收入。私人可取消投资须先保留运营资金与欠薪，上期亏损或没有真实利润历史时暂停。

建筑从完工当月开始承担维护，未付部分累计为欠款。拆除不退投资，不能拆除市政厅，不能让住房或在岗人员所需岗位不足；维护欠款未清偿的建筑不能拆除。迁址重新校验完整占地及入口。

开局住房底座为3600人，已包含原有城镇住房；地图上初始住宅不再次叠加容量。初始建筑样本由种子控制，可通过新建开局对话框改变。

## 3. 桌面实验室

双击 `economy_lab.bat`，或运行：

```powershell
python -m tools.economy_lab
```

从第0月开始，默认推进1个月。参数调整影响后续月份；下达政策不会重开城市。可以先过1月、下政策，再过第2月观察结果。

- **保存运行 / 载入运行**：保存当前城市、基准城市、完整逐月历史与指令，读取后可继续。
- **保存方案 / 载入方案**：保存参数配置；载入方案明确重建第0月，不冒充恢复经营进度。
- **恢复基准**：重置城市和历史。
- **清空折线**：只清空当前显示起点，不清除城市和报告历史。
- **导出报告**：包含有效配置、真实逐月交易、政策与基准对照。

桌面实验与网页游戏各自持有独立城市，不互相修改存档。批量试算函数`compute_comparison`仍保留给开发验证使用；它从开局重算，与界面持续月进分工不同。

## 4. 经济与人口口径

| 指标 | 当前含义 |
|---|---|
| 总居民 | 全城居民数，不等同于就业或劳动力 |
| 劳动力 | 总居民×劳动参与率，等于就业＋失业 |
| 消费等价人数 | 总居民×消费等价系数，只是需求尺度，不是真实新增人口 |
| 应付工资 | 当期就业计划对应的工资义务 |
| 实付工资 | 本期实际转给居民的工资；包含月间雇佣预付时以交易记录解释 |
| 累计未偿工资 | 按雇主和居民归属记录的工资债权，偿付后才减少 |
| 财政变动 | 本期政府真实交易净流，包含月间政策和建设付款 |
| 容纳人数 | 结构岗位、资金、投入及持续经营条件共同约束的上界 |
| 行业目标 | 根据有购买预算的需求计划反推的期望用工，不保证招满 |

金额以整数分存储，100分=1 CR。交易有付款者和收款者，原料与标准交付包均核对期初、生产/采购、消耗/交付和期末。不变量（通俗比喻：每月必须对上的账）只检查数据，不悄悄修改人数或余额。

人口出生/死亡率是**年度游戏参数**，换算到月并保留小数余量，不声称这些弹性已由实证回归验证。参考GNI、老龄系数及出生/死亡延迟字段暂为兼容保留，未开放为已生效玩法。

当前仍是七行业标准交付包单城模型。不能将其解释为完整17类商品、独立运输、贷款本金债权、五城迁移或现实经济预测。住房拥有真实容量和建设代价；完整租售产权、逐户入住、世界迁移尚属后续路线。

## 5. 存档与兼容

网页存档默认位于`saves/industry-slot.json`，再次保存前保留上一份为`industry-slot.bak`。写入先完成编码和临时文件，再替换正式文件；读取失败保留当前城市。

运行状态版本为`IndustryEconomy.STATE_VERSION`，与场景配置版本分开。旧状态缺少人口余量、欠薪债权、政策或交易历史时明确拒绝加载，不用开局值静默填补。旧文件不会在启动或读取失败时被改写。需要保留旧进度时，先另存原文件，再在对应历史版本中查看或导出。

未知版本、缺字段、损坏JSON、负余额、无来源库存、非法地图和不一致的月报缓存会拒绝读取。存档是本地数据，不提供加密签名或抵御蓄意重写全部账目的防作弊保证。

## 6. 配置及调用结构

```text
玩家操作
├─ 地图：frontend → game_api
├─ 行业经营：frontend/industry → industry_api
└─ 桌面：economy_lab → LabSession
   └─ 共用 IndustryEconomy
      ├─ industry_model：行业容量、吸引力与人员匹配
      ├─ industry_settle：采购、消费、租金与外部成交
      ├─ demography：人口变化
      ├─ map_economy / map_geometry：建筑月结与空间约束
      └─ industry_state：运行存档校验
```

网页同一城市的读写使用一把锁串行处理；经济每月在副本上核对成功后提交，不开第二套经济时钟。桌面使用一个后台工作线程，过期结果不会覆盖当前修订。

| 配置 | 用途 |
|---|---|
| `data/economy_v2/industry_lab.json` | 单城开局、交易预算、价格反馈和控件 |
| `data/economy_v2/industry_labor.json` | 行业容量、吸引力及流动规则 |
| `data/economy_v2/industries.json`、`cohorts.json`、`wallets.json` | 行业、居民群组与期初账户 |
| `data/buildings.json` | 建筑外观、尺寸和入口 |
| `data/building_economy.json` | 建筑投资、维护、岗位及住房效果 |
| `data/templates/river_town.json` | 地形、道路、地标和初始住宅候选 |
| `data/economy_v2/runtime_validation.json` | 公开的长期验收门槛 |

## 7. 验证与开发路线

```powershell
python -m pytest -q
python -m scripts.check_industry_gui
python -m scripts.check_single_city_browser
```

浏览器验收需安装`playwright`和Chromium，采用独立端口、独立服务与临时存档。它真实点击表单和地图，核对实际付款、完工、政策、存读档及刷新后的数据，不将截图或接口可用视为整款游戏通过。桌面验收运行真实Tk事件循环和控件回调，不冒充操作系统鼠标验收。

最新工作见[实施计划](docs/02_开发规划/单城经济修复与月进交付实施计划-2026-10-16.md)、[更新日志](CHANGELOG.md)及[文档导航](docs/00_文档导航.md)。原型旧说明已移入历史目录，不能作为当前功能承诺。

后续路线：先做 24 个月玩家试玩与月报解释，再实现**游戏结束机制（月初报告极度异常 → 市长下台事件 → 游戏结束）**与世界地图渲染层（含 NPC 城市节点），然后扩展基础贷款、关键商品与运输、少量对手城市、公共服务与长期政治。**经济崩溃首先判定为玩家责任**，不在经济内核层面追求 120 月长期健康门。旧预设校准器不会把静态阈值检查当成五城长期实跑通过。详见[游戏最终设计要点与校长修正](docs/03_设计规范/游戏最终设计要点与校长修正-2026-10-16.md)。
