# BIPOLE · 双极城市纪事

魔导城市经营原型。当前使用同一套七行业经济状态驱动地图、行业经营页面与桌面实验室；按月决策和结算。

## 1. 启动

需要Python 3.11或以上，以及Tk桌面组件。首次安装依赖：

```powershell
python -m pip install -r requirements.txt
python -m backend.app
```

也可双击 `start.ps1`，浏览器打开 [城市地图](http://127.0.0.1:8876/)；[行业经营与市政政策](http://127.0.0.1:8876/industry)和地图共享同一个城市，切换页面不会重置月份。[世界地图](http://127.0.0.1:8876/world)是独立的 `/world` 页面，玩家在此查看 5 座 NPC 城市节点与友好度关系，与原城市共享同一存档与月份时钟。

启动总是新城市，不自动读取或覆盖旧存档。服务仅供本机单玩家使用。可通过`BIPOLE_PORT`更换端口、`BIPOLE_SAVE_DIR`指定独立存档目录。

## 2. 如何经营

1. 查看政府现金、就业、行业经营现金和住房，决定预算用途。
2. 选择建筑，在草地放置；完整占地不能重叠或占用道路，黄色入口必须接道路。按R旋转。
3. 点击合法地块，市政府真实付款给工业施工；下一次月结完工。未完工不增加岗位或住房。
4. 工坊和集市增加岗位上限、生产设施及原料需求；实际就业取决于资金、需求和供货。住宅增加住房，不增加农业岗位。
5. 推进一个月，查看真实工资、销售、财政、人员流向、维护欠款和政策结果。
6. 在行业页面可发放补贴、雇佣公务员、发失业救济、限招、限裁及退还已缴行业税。持续政策从下一次结算开始，N月恰好覆盖N次月结；限裁不保证企业有钱足额发薪。
7. 保存后可以读取并继续同一条经营路径。存档保留施工、建筑能力、政策、欠薪及逐月历史。

新增公务员需要当场支付预付工资，并形成持续岗位计划，后续月份仍承担工资。补贴和救济有真实付款方；退税不能超过已缴未退税额或国库可支付余额。不能反复执行同一个请求来重复领取或建造。

市政采购的原料归市政持有，企业实际领用这批原料时向市政付款，回收采购周转资金；原有外部市场库存仍向外部支付。贸易支持金是单独的现金支持，不能当作原料采购收入。私人可取消投资须先保留运营资金与欠薪，上期亏损或没有真实利润历史时暂停。

建筑从完工当月开始承担维护，未付部分累计为欠款。拆除不退投资，不能拆除市政厅，不能让住房或在岗人员所需岗位不足；维护欠款未清偿的建筑不能拆除。迁址重新校验完整占地及入口。

开局住房底座为3600人，已包含原有城镇住房；地图上初始住宅不再次叠加容量。初始建筑样本由种子控制，可通过新建开局对话框改变。

## 3. 桌面实验室

双击 `economy_lab.bat`，或运行：

```powershell
python -m tools.economy_lab
```

从第0月开始，默认推进1个月。参数调整影响后续月份；下达政策不会重开城市。可以先过1月、下政策，再过第2月观察结果。

- **保存运行 / 载入运行**：保存当前城市、基准城市、完整逐月历史与指令，读取后可继续。
- **保存方案 / 载入方案**：保存参数配置；载入方案明确重建第0月，不冒充恢复经营进度。
- **恢复基准**：重置城市和历史。
- **清空折线**：只清空当前显示起点，不清除城市和报告历史。
- **导出报告**：包含有效配置、真实逐月交易、政策与基准对照。

桌面实验与网页游戏各自持有独立城市，不互相修改存档。批量试算函数`compute_comparison`仍保留给开发验证使用；它从开局重算，与界面持续月进分工不同。

## 4. 经济与人口口径

| 指标 | 当前含义 |
|---|---|
| 总居民 | 全城居民数，不等同于就业或劳动力 |
| 劳动力 | 总居民×劳动参与率，等于就业＋失业 |
| 消费等价人数 | 总居民×消费等价系数，只是需求尺度，不是真实新增人口 |
| 应付工资 | 当期就业计划对应的工资义务 |
| 实付工资 | 本期实际转给居民的工资；包含月间雇佣预付时以交易记录解释 |
| 累计未偿工资 | 按雇主和居民归属记录的工资债权，偿付后才减少 |
| 财政变动 | 本期政府真实交易净流，包含月间政策和建设付款 |
| 容纳人数 | 结构岗位、资金、投入及持续经营条件共同约束的上界 |
| 行业目标 | 根据有购买预算的需求计划反推的期望用工，不保证招满 |

金额以整数分存储，100分=1 CR。交易有付款者和收款者，原料与标准交付包均核对期初、生产/采购、消耗/交付和期末。不变量（通俗比喻：每月必须对上的账）只检查数据，不悄悄修改人数或余额。

人口出生/死亡率是**年度游戏参数**，换算到月并保留小数余量，不声称这些弹性已由实证回归验证。参考GNI、老龄系数及出生/死亡延迟字段暂为兼容保留，未开放为已生效玩法。

当前仍是七行业标准交付包单城模型。不能将其解释为完整17类商品、独立运输、贷款本金债权、五城迁移或现实经济预测。住房拥有真实容量和建设代价；完整租售产权、逐户入住、世界迁移尚属后续路线。

## 5. 存档与兼容

网页存档默认位于`saves/industry-slot.json`，再次保存前保留上一份为`industry-slot.bak`。写入先完成编码和临时文件，再替换正式文件；读取失败保留当前城市。

运行状态版本为`IndustryEconomy.STATE_VERSION`，与场景配置版本分开。旧状态缺少人口余量、欠薪债权、政策或交易历史时明确拒绝加载，不用开局值静默填补。旧文件不会在启动或读取失败时被改写。需要保留旧进度时，先另存原文件，再在对应历史版本中查看或导出。

未知版本、缺字段、损坏JSON、负余额、无来源库存、非法地图和不一致的月报缓存会拒绝读取。存档是本地数据，不提供加密签名或抵御蓄意重写全部账目的防作弊保证。

## 6. 配置及调用结构

```text
玩家操作
├─ 地图：frontend → game_api
├─ 行业经营：frontend/industry → industry_api
└─ 桌面：economy_lab → LabSession
   └─ 共用 IndustryEconomy
      ├─ industry_model：行业容量、吸引力与人员匹配
      ├─ industry_settle：采购、消费、租金与外部成交
      ├─ demography：人口变化
      ├─ map_economy / map_geometry：建筑月结与空间约束
      └─ industry_state：运行存档校验
```

网页同一城市的读写使用一把锁串行处理；经济每月在副本上核对成功后提交，不开第二套经济时钟。桌面使用一个后台工作线程，过期结果不会覆盖当前修订。

| 配置 | 用途 |
|---|---|
| `data/economy_v2/industry_lab.json` | 单城开局、交易预算、价格反馈和控件 |
| `data/economy_v2/industry_labor.json` | 行业容量、吸引力及流动规则 |
| `data/economy_v2/industries.json`、`cohorts.json`、`wallets.json` | 行业、居民群组与期初账户 |
| `data/buildings.json` | 建筑外观、尺寸和入口 |
| `data/building_economy.json` | 建筑投资、维护、岗位及住房效果 |
| `data/templates/river_town.json` | 地形、道路、地标和初始住宅候选 |

## 8. 游戏结束机制（M24 经济触发器）

2026-10-16 校长修正要求：**经济崩溃首先判定为玩家责任**，不在经济内核层面追求 120 月长期健康门。M24 实现"月初报告极度异常 → 市长下台事件 → 游戏结束"。

**5 条触发规则**（外置于 `data/governance_triggers.json`，可调）：

| 规则 | 阈值 | 宽限期 | 类型 |
|---|---|---|---|
| 失业率危机 | ≥ 30% | 3 月 | grace_period |
| 政府现金破产 | ≤ -1000 CR | 3 月 | grace_period |
| 累计欠薪失控 | ≥ 1000 CR | 2 月 | grace_period |
| 人口锐减 | 单月 -20% | 0（立即） | immediate |
| 失业 + 欠薪同时爆发 | — | 0（立即） | multi |

**触发后行为**：
- `IndustryEconomy._trigger.is_game_over = True`
- `advance(months=N)` 在触发月立刻 `break`，不再推进后续月份
- REST `/api/industry/commands` 除 `new_game` / `save` / `load` 外一律 409
- REST `/api/world/advance` 玩家下台时返回 409，NPC AI 与世界时钟冻结
- 前端 `/industry` 顶部红色横幅 + 月进按钮置灰
- 前端 `/world` 玩家城金色光晕变灰
- 玩家可 `new_game` 开新城市，或 `load` 旧存档（保留历史月报供复盘）

**只读不写**：触发器只读 `last_report`，不修改经济数据，不影响 `assert_invariants()` 守恒检查。这是核心约束，让"游戏结束"成为经济生态的一部分而非内核 bug。

详细设计见 [经济触发器与市长下台-M24](docs/03_设计规范/经济触发器与市长下台-M24-2026-10-16.md)。

## 9. 世界地图与 NPC 城市

`/world` 页面是独立的 Web 入口，与原城市 `/` 共享同一个存档与月份时钟。世界地图上 5 座 NPC 城市（禾谷镇/河湾镇/碧涛港/辉月学城/铁壁关）各自后台真实驱动一套 `IndustryEconomy`，与玩家城市使用**同一套七行业内核**但配置不同（人口基数、行业偏向、税率、AI 市长偏好）。

### 友好度与可见等级

| 友好度 | 等级 | 解锁字段 |
|---|---|---|
| 0—20 | Lv.0 陌生人 | 仅城市名 + 千人量级人口 |
| 21—40 | Lv.1 认识 | + 百人量级劳动力 |
| 41—60 | Lv.2 友好 | + 7 行业就业 + 财政 |
| 61—80 | Lv.3 盟友 | + 月产（粮食/原料库存） |
| 81—100 | Lv.4 完全开放 | 全部字段（月贸易额、政府现金覆盖月数） |

字段被锁定时显示「？？？」占位，玩家可由此判断「还有可探索的字段」但拿不到值——信息差是后续外交/贸易玩法的基础。

### AI 市长可做什么？

每 NPC 城市后台跑一个 AI 市长，每个月从下列候选动作里挑 1—2 个执行，按综合指数（0.4·就业 + 0.3·财政 + 0.2·欠薪 + 0.1·人口）和行业偏好加权打分，并受预算约束。

- **可调**：税率（向偏好收敛，步长 0.02）、行业补贴、失业救济、雇佣公务员、裁员、限时禁止招/裁、市政采购
- **不可调**：基础参数、跨城资金、借贷、建设（这些动作不会出现在 NPC 城市的命令流水里）

玩家可在 NPC 详情面板看到 AI 市长最近 6 条动作（含时间戳与摘要），作为后续玩家解读 NPC 意图的入口。

### 参数分层

| 层级 | 数据类 | 谁共享 | 例子 |
|---|---|---|---|
| 世界级 | `WorldState` | 5 城市共享 | 5 城市坐标、距离矩阵、参考通胀、参考消费 |
| 国家级 | `DiplomacySystem` | 玩家城市视角共享 | 友好度、贸易量、关系事件 |
| 城市级 | 每座 `IndustryEconomy` | 每城独立 | scenario、人口基数、行业容量、税率、市长决策 |

世界级与国家级在 `data/world_map.json` 单一来源；城市级每座 NPC 城市从 `npc_mayor_profiles.json` 读取 archetype + 偏好配置，启动时一次性构建独立 IndustryEconomy。

## 10. 玩家外交行动（M26）

M26 让 NPC 城市从"旁观者"变成"可交互对手"。玩家可在 `/world` 详情面板发起 5 类外交行动，主动改变 NPC 友好度。

| 行动 | 友好度变化 | 限制 |
|---|---|---|
| 贸易协议 | +1/月 | 月限 3 次；需可见等级 ≥ 1 |
| 援助（叙事） | ceil(金额/100) | 月限 1 次；cooldown 2 月 |
| 开放移民 | +3 | 月限 2 次；cooldown 1 月 |
| 公开声明 | ±2 | 月限 1 次 |
| 征收关税 | -10 | 月限 1 次；cooldown 1 月 |

**核心约束（M26 阶段）**：所有行动**不实际扣款**，仅修改友好度。这避免破坏 IndustryEconomy 守恒。aid 标注为"叙事"让校验逻辑知道无需对照 cash。

**REST**：
- `POST /api/world/diplomacy_action` — 玩家发起；target_city_id 不存在返回 404；玩家下台返回 409；未知 action_key 返回 422
- `GET /api/world/diplomacy_actions/{city_id}` — 该城市最近 50 条玩家行动

详细设计见 [外交行动接口-M26](docs/03_设计规范/外交行动接口-M26-2026-10-16.md)。

## 11. NPC-NPC 贸易网（M27）

M27 让 5 座 NPC 城市之间产生自动贸易流，玩家可在世界地图上看到蓝色虚线（叠加在原关系连线上）+ 月贸易额数字。

| 规则 | 阈值 / 公式 |
|---|---|
| 友好度阈值 | ≥ 30 才产生贸易流（初值 50 全通过） |
| 月贸易额 | clamp(base × (friendly/100) × 1/(1+distance/100), min=100, max=5000) CR |
| 友好度月增 | 双方 +1/月（叙事友好度信号，不实际转账） |

**核心约束**：M27 阶段所有贸易**不实际转账**——仅生成"贸易流记录"作为友好度信号。后续 M27.1 阶段可扩展为 IndustryEconomy.transfer_to_npc() 真实转账（须扩展守恒路径）。

**REST**：`/api/world/state` 新增 `npc_trade_routes` 字段（每条流含 city_a / city_b / month / volume_cr / friendliness_delta_per_side）。

**前端**：地图叠加 6 条 NPC-NPC 蓝色虚线（`stroke-dasharray="5,3"`），中段标注月贸易额（取整 CR）。

## 12. 行业情报（M28）

M28 让玩家向**盟友级**（friendly ≥ 61）NPC 城市派间谍，获取**完整月报**（不脱敏）。这是 M25 设计文档规划的"信息差"玩法扩展。

| 规则 | 阈值 / 公式 |
|---|---|
| 最低友好度 | visible ≥ 3（盟友级，friendly ≥ 61） |
| 成本 | 2000 CR（叙事代价，不实际扣款） |
| 月限 | 1 次 / 城市 |
| 冷却 | 1 月 |
| 被发现概率 | friendly ≥ 70 → 10%；friendly < 70 → 30% |
| 被发现惩罚 | 友好度 -20 |

**核心约束**：M28 阶段**不实际扣款**——与 M26/M27 一致，避免破坏 IndustryEconomy 守恒。后续 M28.1 可引入 `IndustryEconomy.spend_on_espionage(cost_cr)` 真实扣款。

**REST**：
