# BIPOLE · 双极城市纪事

基于现有设计稿的本地 Web 城市经营初版。Python 后端维护经营状态，浏览器显示等距城镇；所有建筑、树木、河流与人物素材均由代码绘制。

作者：**iris0heartmade**。项目仓库：[iris0heartmade/Bipolar_City](https://github.com/iris0heartmade/Bipolar_City)。使用原仓库的 [MIT 许可证](LICENSE)。

## 1. 启动与试玩

需要 Python 3.11 或更新版本。首次使用建议在项目目录创建虚拟环境（通俗比喻：项目独立的工具箱）：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m backend.app
```

当前开发环境已经具备依赖，也可直接运行 `python -m backend.app`，或运行 `start.ps1`。浏览器打开 [本地游戏](http://127.0.0.1:8876)。必须通过后端打开，不能双击 HTML 文件。

端口被占用时，更改 `data/server.json`，或在 PowerShell 当前窗口运行：

```powershell
$env:BIPOLE_PORT = '8877'
python -m backend.app
```

试玩顺序：

1. 选择左侧联排住宅或工人公寓；沿道路寻找入口可接通的空地。
2. 按 R 或底部旋转按钮调整方向。绿色表示可建、红色表示不合法、黄色小格表示入口。
3. 点击地图放免费蓝图，再确认施工；资金此时扣除。
4. 点击继续，服务端按日施工；或保持暂停，点击推进一个月。住宅竣工后才提供容量，居民按月迁入。
5. 查看建筑详情、施工队列和财政账本，再保存。读取须确认替换未保存进度。

拖动地图平移，滚轮/加减按钮缩放，Esc 退出建造。手机选择建筑后会自动滚回地图。格子按钮显示空间约束，住房按钮显示住宅容量。

服务启动总是生成测试开局；不会自动读取存档。点击读取恢复已有城市。保存位置是 `saves/slot1.json`，上一份保留为 `slot1.bak`。新开局不会删除存档。关闭页面不会暂停服务端时间，请先暂停或关闭服务。

## 2. 已实现功能与边界

| 已实现 | 具体行为 |
|---|---|
| 已有城镇开局 | 固定河流、道路与桥，种子控制初始住宅选择 |
| 格子建设 | 整数格、多格占地、四向旋转、冲突/地形/道路入口校验 |
| 施工 | 免费蓝图 → 扣费批准 → 待施工 → 施工中 → 竣工；重复请求不重复扣费 |
| 人口与财政 | 容量和岗位约束迁入；按月税收与维护；逐笔现金账目 |
| 时间 | 暂停、0.5×/1×/2×、手动推进一个月；模拟不依赖画面帧率 |
| 存读档 | 完整状态校验、配置版本校验、原子保存和备份；恢复失败保留当前城市 |
| 游戏界面 | 等距地图、分类建造、统计、建筑详情、实际人口记录、纪事与施工队列 |

原型地图为可配置的 28×28 测试城，替代建议中的 64×64，以便初版完整呈现。市政厅为固定地标；可新建住宅、公寓、集市、工坊、花园。道路暂固定，不支持新建道路、拆除或升级已完成建筑。

所有住房当前为市政持有；税收使用简化人口公式，没有房屋出售、租金或贷款。集市/工坊只提供简化岗位与维护，不产生虚假的库存与商户收入；花园暂无环境加成。没有 NPC 城市、银行、科技、议会、人物养成或 20 年评分。城名和数值都是测试内容，不是小说正史。

服务面向本地单玩家，不支持多用户隔离或公网认证。版本/配置变化时旧存档明确拒绝加载，目前未实现跨版本迁移。核心不使用运行期随机数，未来加入随机事件时必须持久化随机状态。

```text
│  ├─ model/world.py          世界与建筑模型
│  ├─ systems/

│  │  ├─ placement.py         占地、旋转与道路连接
│  │  ├─ construction.py      蓝图、批准、施工与竣工
│  │  ├─ population.py        容量、岗位与迁入
│  │  └─ finance.py           现金与账目
│  └─ persistence/savegame.py 版本化存档
├─ frontend/
│  ├─ index.html              中文页面结构
│  ├─ css/style.css           桌面/手机布局
│  ├─ assets/emblem.svg       自绘标志
│  └─ js/
│     ├─ main.js              页面入口与同步
│     ├─ api.js               后端通信
│     ├─ isometric.js         坐标变换与旋转
│     ├─ art.js               自绘建筑与自然素材
│     ├─ renderer.js          地图、图层与小地图
│     ├─ controls.js          鼠标/触摸/键盘交互
│     └─ ui.js                面板、账本和提示
├─ data/                     建筑、经济、服务配置与地图模板
├─ tests/                    模拟/API/时钟/存档测试
├─ scripts/browser_check.py  独立城市的真实浏览器验收
├─ docs/                     计划与验收记录
├─ saves/                    本地存档
├─ logs/                     运行日志（运行后生成）
├─ artifacts/                验收截图与报告（运行后生成）
├─ start.ps1                 Windows 启动入口
└─ CHANGELOG.md              中文更新日志
```

调用顺序：Web 操作 → HTTP 命令入口 → 世界服务 → 建设/财政等系统 → 权威世界状态 → 页面快照。HTTP（通俗比喻：前后台传递办事单的通道）仅传递意图与数据，页面不能自行增加现金或人口。

前端和后端是组合关系，不使用多层继承。仅一个服务端模拟循环，所有读写和时间推进通过同一锁串行处理。暂停关闭时间更新但保留页面交互；普通命令不会清空部分日计时。存档成功校验后整体替换世界。

## 4. 配置与扩展

| 文件 | 可调整内容 |
|---|---|
| `data/buildings.json` | 占地、入口、费用、施工日数、容量、岗位、维护、类型 |
| `data/balance.json` | 初始资金、人口、税收、月度迁入、日历和速度基准 |
| `data/templates/river_town.json` | 地图尺寸、河流、道路、地标与初始住宅候选位置 |
| `data/server.json` | 本地监听地址与端口 |

金额以整数分币存储，界面除以 100 显示银镑。改经营配置后存档配置校验会阻止混用旧数值。增加建筑定义后，还需在 `art.js` 提供对应绘图；改地图时必须保证候选住宅和地标可建。

后续先完善住宅销售、公房与就业，再加入银行、NPC 贸易、科技、人物和议会。扩展功能应放入对应系统，由统一调度器调用；不能另开一套经济循环。

## 5. 验证与文档

```powershell
python -m pytest -q
```

真实浏览器检查需要额外工具，首次安装：

```powershell
python -m pip install -r requirements-dev.txt
python -m playwright install chromium
python -m scripts.browser_check
```

浏览器检查会启动独立服务、使用临时存档并在结束后关闭该服务，不改变试玩城市。检查真实鼠标/键盘/触摸操作，截图与结果保存到 `artifacts/`。当前已验证 38 项自动测试和桌面/手机完整流程，详见 [验收记录](docs/验收记录.md)。
