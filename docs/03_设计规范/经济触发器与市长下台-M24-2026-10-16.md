## 1. 设计目标

**M24 = 把"市长下台是游戏内容的一部分"从口号变成可玩机制。**

2026-10-16 校长修正明确：

> 经济崩溃的责任 = 玩家责任（不在经济内核层面追求 120 月长期健康门）。
> 月初报告独立判定器：单项持续多月极度异常进入宽限期；多项同时触发直接下台。
> 触发器只读不写，不影响经济守恒。

M24 让玩家城市在经济走向崩溃时获得"二次确认"窗口（宽限期），但如果持续恶化或多重危机叠加，城市就被宣布"游戏结束"，玩家可以选择重新开始。

## 2. 游戏体验：市长下台是什么样子

### 触发场景

玩家玩了几十个月后，城市经济持续恶化：

```
第 17 月：失业率 31%（超过 30% 阈值），政府现金 -500 CR
第 18 月：失业率 32%，政府现金 -800 CR
第 19 月：失业率 35%，政府现金 -1200 CR
```

此时满足"失业率连续 3 月 ≥ 30%"，加上"政府现金 ≤ -1000 CR 持续 3 月"——两个 grace 都在第 19 月同时触发。玩家看到：

**红色横幅「市长已下台 — 失业率危机（≥30%）；政府现金破产（≤-1000 CR）」**

下方有「月进 →」按钮但已经**置灰禁用**，旁边的红色提示写「⚠ 城市已结束，请点上方红色横幅"新建城市"重启。」

世界地图 `/world` 上，玩家城市的金色光晕变成灰色——你不再是这座城市的主角了。

### REST 层的选择

```bash
# 月进返回 409（HTTP Conflict）
$ curl -X POST /api/industry/commands -d '{"type":"advance","months":1}'
{"detail":{"error":"game_over","reasons":["失业率危机（≥30%）","政府现金破产（≤-1000 CR）"]}}

# 世界地图也冻结
$ curl -X POST /api/world/advance -d '{"months":1}'
{"detail":{"error":"game_over","message":"市长已下台，世界地图已冻结。"}}

# 但存档仍可读取（保留历史月报供复盘）
$ curl -X POST /api/industry/commands -d '{"type":"load"}'
200 OK

# 新建城市 OK
$ curl -X POST /api/industry/commands -d '{"type":"new_game","seed":42}'
200 OK  # is_game_over=false 重新开始
```

## 3. 5 条触发规则

| key | 阈值 | 宽限期 | 类型 | 含义 |
|---|---|---|---|---|
| `unemployment_crisis` | `unemployment_rate >= 0.30` | 3 月 | grace_period | 三成人口失业超过 3 个月，城市社会基础动摇 |
| `government_bankruptcy` | `government_cash_cents <= -100000`（-1000 CR） | 3 月 | grace_period | 政府现金连续 3 月为负，无法维持基本服务 |
| `wage_arrears_runaway` | `wage_arrears_cents >= 100000`（1000 CR） | 2 月 | grace_period | 累计欠薪超过 1000 CR 持续 2 月，企业和市民信任崩塌 |
| `population_collapse` | `population_change_rate <= -0.20` | 0（立即） | immediate | 单月人口锐减 20% 以上（瘟疫/战乱/大规模外逃），立即触发 |
| `civil_unrest_multi` | — | 0（立即） | multi | 失业率危机 + 欠薪失控同时 breach → 社会动荡，直接下台 |

**严重度（severity）**：
- `grace_period`：连续 N 月 breach 才触发
- `immediate`：单月 breach 即触发
- `multi`：依赖其他触发器 streak 同步（`all_of` 列表中所有项都 ≥ 1 月 streak）

阈值与宽限期全部外置于 `data/governance_triggers.json`，玩家可调（这本身也是经济内核"不追求长期健康"的体现——难度可以由玩家或运营者定制）。

## 4. 玩家能做什么

下台后玩家有 **3 种选择**：

| 操作 | 用途 | 何时用 |
|---|---|---|
| `new_game` | 重建一个新城市（重置月份、scenario、触发器） | 想从头再来 |
| `save` | 保存当前下台状态 | 想保留这个"失败案例"留作对比 |
| `load` | 读取存档 | 想从历史存档的某个月份继续 |
| 其他（`advance`、`set_parameter`、`mayor_command`、`purchase_external`） | — | 全部 409 拒绝 |

注意 **存档永远可读取**——即使下台了，历史月报、`report_history` 都还在，玩家可以复盘"哪个月开始出问题"。

## 5. 参数设计与宽限期

### 为什么需要宽限期？

一个月的数据波动可能是随机噪声（如一次性事件），连续多月才反映"系统性危机"。宽限期给玩家**自救窗口**。

例如：失业率 32% 持续 1 月，可能只是某个行业的季节性波动，玩家有时间推出"行业补贴 + 救济"政策把失业率压回去；如果第 2 月就触发下台，玩家根本来不及反应。

### 为什么需要 immediate 类型？

clear immediate 处理"系统性崩溃"——如单月人口锐减 20%（瘟疫/战乱），任何补救都来不及。这种场景下"宽限期"反而是给玩家虚假的希望。

### 为什么需要 multi 类型？

multi 处理"显式不独立事件的同时爆发"——例如失业 + 欠薪同时爆发，意味着：
1. 大量裁员（失业率上升）
2. 同时大量工资欠付（欠薪累积）

这两件事单独看可能还在 grace 期内，但同时出现意味着社会系统性危机，应当立即触发。

### 6.2 数据契约 `data/governance_triggers.json`

```jsonc
{
  "_comment": "经济触发器阈值与宽限期...（参见上文 §3）",
  "triggers": {
    "unemployment_crisis": {
      "metric": "unemployment_rate",
      "comparison": ">=",
      "threshold": 0.30,
      "grace_months": 3,
      "severity": "grace_period",
      "label": "失业率危机（≥30%）"
    },
    // ... 4 条其他规则
    "civil_unrest_multi": {
      "type": "multi",
      "all_of": ["unemployment_crisis", "wage_arrears_runaway"],
      "severity": "immediate",
      "label": "失业 + 欠薪同时爆发"
    }
  }
}
```

**字段含义**：
- `metric`：`last_report` 中读取的指标名（`unemployment_rate` 是派生指标，从 `unemployed / labor_force` 计算）
- `comparison`：`>=` / `<=` / `>` / `<` / `==`
- `threshold`：触发阈值
- `grace_months`：连续触发月数（0 = 立即）
- `severity`：`grace_period` / `immediate`（multi 类型自动为 immediate）
- `type`：`single`（默认）/ `multi`
- `all_of`：multi 类型的依赖项 key 列表
- `label`：触发后显示的中文描述

### 6.3 EconomicTrigger 类

```python
class EconomicTrigger:
    def __init__(self, config=None):
        self.config = config or load_governance_triggers()
        self._streak = {key: 0 for key in self.config}
        self._prev_report = None
        self._game_over = False
        self._reasons = []

    def evaluate(self, current_report: dict) -> bool:
        """读取 last_report，更新 streak；若触发 game_over 则返回 True。"""
        if self._game_over:
            return True
        # 1. 遍历所有 single 触发器
        # 2. multi 触发器检查 all_of 中所有项 streak ≥ 1
        # 3. 满足条件的加入 newly_breached
        # 4. 若 newly_breached 非空 → _game_over = True, _reasons = [labels]
        # 5. 返回 self._game_over
```

**evaluate 流程详解**：

```
for key, cfg in self.config.items():
    if cfg.type == 'multi':
        continue
    value = _read_metric_for(cfg.metric, current_report)
    if value is None:
        self._streak[key] = 0          # 缺数据 → 重置
        continue
    if _compare(value, cfg.comparison, cfg.threshold):
        self._streak[key] += 1         # breach → streak +1
        if cfg.severity == 'immediate' or self._streak[key] >= cfg.grace_months:
            newly_breached.add(key)
    else:
        self._streak[key] = 0          # 恢复 → 重置

# multi 单独处理
for key, cfg in self.config.items():
    if cfg.type != 'multi':
        continue
    if all(self._streak[s] >= 1 for s in cfg.all_of):
        newly_breached.add(key)
```

**streak 重置时机**：单月 breach → streak +1；不 breach → streak = 0。所以"宽限期"是"连续 breach 的月数"，不是"最近 N 月内 breach 月数"。

## 7. 只读不写：与经济守恒的关系

**这是 M24 设计最重要的约束。**

触发器只读取 `last_report` 中的字段，**绝不修改任何经济数据**：

- ❌ 不修改 `cash` / `population` / `unemployed_by_group` / `last_report`
- ❌ 不调用 `city.advance()` 内部任何 mutator 函数
- ❌ 不修改 `_active_policies` / `_last_policy_actions`
- ✅ 只读 `last_report.unemployment` / `last_report.labor_force` / `last_report.government_cash_cents` 等
- ✅ 只更新自己内部状态（`_streak` / `_game_over` / `_reasons` / `_prev_report`）

所以即使触发器误判（譬如误把 score 函数返回 0 当作失业），经济内核还是干净的；触发 game_over 后玩家存档、`report_history`、`transactions` 全部完整保存，可读可分析。

更精妙的是：玩家可以在下台后通过 `load` 读取存档，复盘"哪几个月开始出问题"，然后**不修改存档**就直接 `new_game` 开新城市重试。这是"经济生态的一部分"而非"内核 bug"的真正含义。

## 8. 边界与限制

- **玩家不能取消 game_over**：触发后只能 new_game / save / load。设计意图：避免玩家"撤销触发"破坏游戏结果完整性。
- **game_over 后 IndustryEconomy 不允许 advance / set_parameter / mayor_command / purchase_external**：这些操作修改经济状态，违反"游戏已结束"的语义。
- **存档读取仍可用**：`load` 不修改经济数据，只是把存档内的数据 `from_dict` 重建到一个新的 `IndustryEconomy`。所以玩家可以"读档查看历史"，但仍不能让那座城市继续推进。
- **AI 市长不会在 NPC 城市上触发 game_over**：M24 只挂在玩家城市 `IndustryEconomy` 上。NPC 城市用 `AiMayor` 的综合指数决策（不会下台）；玩家看到的是 NPC 城市经济指标的演化，但不是"他们输了"。
- **触发器不会被玩家操作重置**：玩家可以通过 `purchase_external` / `mayor_command` 改善 `last_report` 字段，触发器读到的指标会自然好转，streak 会自然归零。这是 "grace period" 的核心机制。
- **阈值可调但需重启**：`data/governance_triggers.json` 是启动时读取，玩家在游戏中改文件不会生效（这是有意为之，避免玩家"读档时作弊"）。

## 10. 后续路线

### M24.1：议会评价与不信任案（M18 配合）

校长修正提到"议会评价/不信任案/任期回顾由既有 M18 配合；M18 不到位前以'中央直接委派结果'过渡"。

M24 现在是"中央直接委派结果"过渡。M18 议会评价成熟后，可以接入：
- 议会评分（来自 last_report 衍生）
- 不信任案（评分 < 某阈值 + 玩家行为触发）
- 任期回顾（每 12 月强制进入 review 流程）

### M24.2：玩家主动投降

玩家可以主动发起 "resign"，立即触发 game_over。这给玩家"止损"选项（例如玩得实在坚持不下去时）。

### M24.3：失败案例分析器

下台后 `/industry` 页面提供"复盘模式"：列出最近 12 月的趋势曲线、关键事件、AI 市长动作（如果有）、政府现金/失业率/欠薪变化曲线。这帮助玩家理解"哪里做错了"。

### M24.4：难易度调节

`data/governance_triggers.json` 提供多个难度预设（简单/普通/地狱），玩家 new_game 时可以选。

### M24.5：胜利条件（180 月稳定）

作为 M24 的"另一面"，可以加一个 `victory_trigger`（180 月持续稳定 → 胜利）。但校长修正明确"不在内核层面追求长期健康门"，所以这是"可选扩展"不是"M24 必备"。
