## 1. 模型结构与设计选择

```text
世界和城市既有经济状态（月末冻结快照）
├─ 行业容纳限度 K_industry：有条件维持运行的员工人数
│  ├─ 已建岗位上限
│  ├─ 当月真实工资资金
│  ├─ 持续收入和有限储备支撑
│  └─ 已分配必要投入能支持的工作量
├─ 行业吸引力 A_industry：劳动者愿意加入/留下的0—100分评价
│  ├─ 实际劳动收入质量
│  ├─ 发薪与现金稳定性
│  └─ 工作环境
├─ 行业用工目标：准备做多少事，需要多少人
│  ├─ 私营部门：订单、销售历史、库存目标
│  └─ 公共/非营利部门：有资金的服务与人员计划
└─ 本城劳动力流动（统一撮合器）
   ├─ 无资金/建筑取消造成的硬退出
   ├─ 需求或经营条件下降造成的渐进缩编
   ├─ 待业者进入有资金的空缺
   └─ 在职者接受更有吸引力的岗位后转行
       └─ 汇总就业和失业 → 工资/生产/城市K/L → 下一月反馈
```

仅对玩家新增两个主指标：**行业容纳限度（人数）与行业吸引力（分数）**。容量利用率、工资覆盖、空缺、用工目标是分项解释，不新增一批全局控制滑条。K与A是计算结果，不允许直接编辑结果以配平。

比较过三种路径：①利润率直接决定人数和吸引力，简单但会误伤教会、公务员和投资期行业；②多项增益连乘，容易放大且难以解释；③容量取真实约束最小值、吸引力采用工作质量加权评分。采用③，能清楚说明“卡在哪里”和“为什么愿意来”。

本轮不修改居民需求体系、城市财政恢复机制、外交关系或进口惩罚。城市人口迁移保持城市层规则；劳动力转行不新增人口。行业自动扩建、定价、采购的完整决策器也不在本文中假定已经实现。

## 2. 现实评价依据与游戏化边界

| 一手来源 | 可以借鉴的事实/结构 | 本模型如何使用 |
|---|---|---|
| [OECD工作质量框架，2015](https://www.oecd.org/en/publications/measuring-and-assessing-job-quality_5jrp02kjw1mr-en.html) | 工作质量包括收入质量、劳动力市场安全、工作环境三个维度 | 用来选A的三个维度；本模型没有计算现实中的收入分布和完整失业保险 |
| [ILO体面劳动指标研究，2002](https://www.ilo.org/publications/working-paper-no-2-measuring-decent-work-statistical-indicators) | 收入、稳定、安全和劳动条件值得分别观察 | 避免把高工资当作唯一就业质量；不引入新的劳动法规玩法 |
| [美国劳工统计局JOLTS定义](https://www.bls.gov/jlt/jltdef.htm) | 岗位空缺要求有岗位和工作、能在相应期间开始、正在招聘 | 区分建筑容量、可持续容量、实际招聘空缺 |
| [美联储产能定义](https://www.federalreserve.gov/releases/g17/capnotes.htm) | 产能强调正常运行条件下可持续的最大产出 | 借鉴“可持续条件”，不把设备标称容量等同于实际开工规模 |

**所有0.60/0.25/0.15评分权重、3个月缓冲、招聘10%、转行5%及5分门槛，均为本游戏设计初值，不是上述机构估计出的现实系数。** 七行业工资和税率来自项目已有设定。参考资料核验日期：2026-10-15。

## 3. 现有参数和新增输入

时间单位为月，金额内部为整数分，1 CR=100分；人数最后为整数。行业i、居民归属群体h；clip把数值限制在指定上下界。下文的“储备”只指已经到账、可动用的现金。

### 3.1 直接复用的行业参数

| 行业 | 基础阶段岗位上限 | 税前工资CR/人/月 | 工资所得税 | 行业正利润税 | 工资付款钱包 |
|---|---:|---:|---:|---:|---|
| AGR 农业 | 300 | 60 | 0 | 0 | 农业经营现金 |
| IND 工业 | 1500 | 90 | 8% | 12% | 工业经营现金 |
| SRV 服务商业 | 600 | 100 | 8% | 15% | 服务经营现金 |
| CHU 教会 | 100 | 75 | 8% | 0 | 教会共用钱包 |
| BNK 银行 | 100 | 100 | 8% | 12% | 银行经营钱包 |
| MAG 魔法学院 | 400 | 90 | 8% | 8% | 学院经营现金 |
| GOV 公务员 | 50 | 75 | 8% | 0 | 市政府工资预算 |

岗位上限不是现有建筑的岗位数；实际J取已完成、可使用建筑岗位与已解锁阶段上限的最小值。长期可由正式建筑/技术规则提高上限。

直接复用 `SectorState` 中的就业E、工资w、经营现金M、商品产能Qbar、已付投入、经营收款、债务及利润数据；生产劳动指数复用0.8。直接复用城市实际生活成本Cneed、现行工资税和账簿付款记录。

### 3.2 必须补齐的输入及可靠性

| 输入 | 单位/口径 | 来源与限制 |
|---|---|---|
| payroll_budget | 分 | 行业/政府已经到账的工资可支付额度；扣除其他已锁定义务，非预计收入 |
| recurring_receipts_history | 最近3个月分/月 | 真实可重复的商品服务收款、有效预算、捐赠等；排除贷款本金、售产权、一次性资本注资 |
| recurring_nonpayroll | 分/月 | 计划运行所需原料、服务、维护、租金、税息等；不含工资和折旧，不重复扣本金 |
| reserve_drawable | 分 | 从同一真实现金预算划出的可消耗储备，不能再次另加一份钱 |
| full_load_inputs / available_inputs | 各自商品单位 | 标准满负荷投入与实际分配给本行业的可用量；城市共享库存必须先分配/锁定，不能各行业重复认领 |
| wage_due / paid / timely_paid | 分/月 | 实际工资负债、实付及按时支付额，不能用报价替代到账 |
| safety_quality / working_time_quality | 0—1 | 有依据的工作场所安全与工时质量；无数据时0.5中性，标明“尚无实测” |
| funded_staff_plan / planned_activity | 人或活动比例 | 有真实资金的公共人员计划、已预算的生产服务计划 |
| X[h,i] / U[h] | 人 | 8群体×7行业就业分布及各群体待业劳动力；保持人口与就业分别核算 |
| fractional_carry | 0—1人 | 招聘/缩编/转行的小数余量，避免20人以下行业永远不变化 |

新行业无历史：持续收入默认0，依靠已到账启动储备获得有限容纳量；不凭空补造销售。首期吸引力的收入只允许使用已经锁定资金的录用工资，信用按0.8先验（通俗比喻：新雇主尚未建立口碑），以后用真实发薪记录取代。无工资资金不形成招聘空缺。历史不足3个月时对已有有效观察权重重归一化；新行业先验不冒称实际历史。开局若使用合成等价历史，必须在种子报告标为校准输入并由真实合同/资金验证。

## 4. 行业容纳限度 K_industry

### 4.1 建筑与当月支付硬边界

```text
J_i = min(已解锁阶段岗位上限, 已完成且可用建筑的岗位合计)
J_cash_i = floor(payroll_budget_i / w_i)
H_i = min(J_i, J_cash_i)
```

H是硬边界（通俗比喻：本期确实存在且能付工资的椅子数量）。工资w必须大于0。必要运营费用、已批准建设、贷款还本付息、共享资金的其他用途先分配，不能把全城现金同时给七行业使用。GOV只用已拨给公务员的额度；BNK先扣贷款放款承诺；CHU先扣其已承诺捐赠与运营款。

没有到账的预计销售和贷款不得计入J_cash；当期已到账预付款只在现金中算一次，不再叠加“合同收入”。预算锁定本身不转移现金，实际工资付款仍只过账一次。

### 4.2 可持续经营资金边界

```text
R_rec_i = median(最近3个月有效的可重复经营支持收入)
B_rec_i = max(0, R_rec_i - recurring_nonpayroll_i)
D_res_i = floor(reserve_drawable_i / T_reserve)       T_reserve = 3月
J_fin_i = floor((B_rec_i + D_res_i) / w_i)
```

历史不足3个月时取已有有效观察的中位数；无历史为0。`reserve_drawable <= payroll_budget`。储备贡献和历史收入只给出持续能力估计，**不是新的可支付现金**；最终仍受J_cash约束，所以不会用历史收入支付不存在的钱。

非工资成本采用本期计划工作量对应的已核价必要成本，不用会计总费用机械替代；税息及本金到期支出分别预留，利润税未确定时使用保守预算上界，不在预算阶段生成真实税收。现金分配不得低估固定租金维护，也不得把扩大生产的新原料需求漏掉。实际支出变化后重算，而非永久沿用首月每人成本。

R_rec对不同部门含义不同：农业/工业/服务/学院为实际营业支持及已拨运营补助；教会含实际可重复捐赠；政府为经批准并有资金的周期工资支持预算；银行含真实金融服务与利息，绝不含放款本金、归还贷款本金或客户不可动用资金。

这使亏损但有储备的行业可以过渡运行；储备耗用后D_res逐步下降。一次巨额启动资金不能让行业永久保持满编。

### 4.3 必要投入边界与生产公式衔接

沿用劳动产出指数γ=0.8。把行业当月产品组合固定成一个标准活动方案：每种产出满负荷为Qbar_g，满负荷所需投入为Ibar_g。不存在的投入配方不强加原料约束。

```text
eta_nonlabor = clip(已生效且真实支持的安全/工时等生产因子乘积, 0, 1)
x_input = min(eta_nonlabor, min_g(available_input_g / Ibar_g))
J_input = floor(J_i * (x_input / eta_nonlabor)^(1/0.8))
```

无正投入需求时 `J_input=J_i`；eta_nonlabor=0时 `J_input=0`；对J_input限制0..J_i。Ibar必须与同一活动方案、同一月份的产出一致；库存中某种商品有100单位不是“可以随便支持100员工”。

这是“这些原料最多支持多少员工有活可干”的反推。资源不足时，可以暂时养着员工等待供货；因此J_input不是当月强制解雇线。

**避免重复处罚：** 生产采用下面同一资源约束，不再把资源比例在新K、用工人数和旧eta_input中反复相乘：

```text
x_labor = eta_nonlabor * (min(E_i,J_i)/max(J_i,1))^0.8
x_real = min(x_labor, min_g(available_input_g/Ibar_g))
Q_actual_g = Qbar_g * x_real
input_used_g = Ibar_g * x_real
```

无投入需求时第二个min视为无限。接入旧生产模块时，旧eta_input须改成“可用投入/本次劳动计划实际所需投入”的条件比例，而非仍按满负荷方案再乘一次。容纳限度变化只引导人员调整，不直接改库存；真实生产才扣投入和加产出。

### 4.4 最终指标与解释

```text
K_industry_i = max(0, min(J_i, J_cash_i, J_fin_i, J_input_i))
```

对外显示整数人，并给出所有并列短板。K是潜在可持续运行人数，不保证有人愿意来，不保证现在全部有订单，也不等同于当前就业E。E可以暂时高于K，前提是E<=H且真实支付待岗工资；软缩编随后逐步调整。

## 5. 行业吸引力 A_industry

### 5.1 收入质量 W

按最近3个月新到旧0.5/0.3/0.2对“每员工实际税后劳动收入”加权，缺历史时重归一。只用本期岗位带来的收入，不把股息、地产租金或经营利润直接当员工工资。

```text
net_wage_m = (paid_wages_m - wage_PIT_m) / employed_m
y_real_i = (weighted_net_wage_i + actual_job_benefit_i) / Cneed_city
y_reference = 90*(1-.08)/50 = 1.656
W_i = clip(.50 + .50*log2(y_real_i / y_reference), 0, 1)
```

已就业人数为0的历史月份不参与人均工资平均；新行业按第3节处理。y_real=0时W=0。对数映射（通俗比喻：涨工资有用，但越高越不容易继续刷满分）避免少数天价工资无限吸人。

农业工资税豁免已经进入净收入，不额外加“农业吸引力BUFF”。Cneed是已经反映本地价格和通胀的成本，不再乘CPI。所有名义工资、成本同时翻倍，W不变。

actual_job_benefit只包括已交付且归属于岗位的住房/餐食等实物福利，以避免的实际生活支出计价且不能高于该项生活篮子成本；必须有真实资产、服务或付款，不得把“农场有附属住房容量”直接按全额福利发给每个员工。只用于评价，不新发一次现金，也不在城市消费里重复算收入。

### 5.2 就业稳定性 S

```text
p_m = timely_paid_wages_m / wage_due_m
p_bar = weighted_mean(p_m, .5/.3/.2)
p = min(p_current, p_bar)              无本期应付工资的新行业使用有标记先验
runway = 可动用经营现金 / 最近有效月必要现金总支出
r = clip(runway / 3月, 0, 1)
S_i = .60*p + .40*r
```

必要支出含工资、原料、租金维护、到期税息及还本等实际义务，不含折旧和可取消扩建；没有有效历史时用已核价本期必要计划，不能除零后假装无限稳定。分母为0且未运行行业，runway默认0，直到有可验证计划。按时率对新欠薪及时响应、对历史信用渐进恢复。

这是简化的岗位稳定性代理，不是OECD完整失业风险指标。政府、教会和银行不会天然获得高分；只要实际发薪可靠、资金缓冲足够，就有同样的得分机会。

### 5.3 工作环境 Q

```text
Q_i = .60*safety_quality_i + .40*working_time_quality_i
```

两个输入均为0..1。无证据时取0.5，标明信息不足；不按行业名称编造“矿工危险、银行轻松、公务员稳定”等固定偏见。安全设备、工作安排改善必须有真实建设/运营条件才能改变输入。

本版先接受已定义的场所安全评价和工时评价，不擅自追加一套劳动法规。城市安全s不自动复制成场所安全评分；宗教既有工时因子不再额外作为Q惩罚。宗教工资容忍仍只在既有工资目标处作用，不再给A加同一项宗教奖励。

### 5.4 合成与平滑

```text
A_raw_i = 100*(.60*W_i + .25*S_i + .15*Q_i)
A_smooth_i = .50*A_previous_i + .50*A_raw_i
A_industry_i = clip(min(A_smooth_i, 100*p), 0, 100)
```

无上一期评分时直接用A_raw，不把新行业从0慢慢爬起。按时率上限是明确的非补偿约束（通俗比喻：拖欠工资不能靠漂亮办公室抵消）；欠薪对收入与信用的作用分别解释，不再额外乘一次产量惩罚。

没有空缺时行业仍可以高吸引力，但不会吸收新员工。利润税不直接减员工A：它先影响真实行业资金和用工条件，实际工资变化再影响A。

## 6. 用工目标与七行业差异

**容纳得下不等于准备招满。** 额外保留一个内部目标T_i，满足0<=T_i<=K_i，不作为第三个主评分。

市场行业先生成有预算的计划活动量x_plan：近期真实销量、有效订单、目标补库存和已分配出口合同共同确定。缺货导致未成交的有效订单可以作为需求证据，但不是已到账资金；单纯点击次数、未付意向或虚构境外需求不可作为保证收入。多产品需先明确活动配方，本版不混合不同产出比例后直接套一个标量。

```text
E_demand_i = ceil(J_i * clip(x_plan / eta_nonlabor, 0, 1)^(1/0.8))
T_private_i = min(K_i, E_demand_i)
T_public_i = min(K_i, funded_staff_plan_i)
```

eta_nonlabor=0时需求用工为0。补库存有真实数量目标，库存超过目标不能继续以“补库存”无限生产；计划产出本身不生成收入。

| 行业 | 目标用工依据 | 特别处理 |
|---|---|---|
| AGR | 本地粮食/原料订单、有效出口、有限储备采购 | 农业免工资税；自产食品不自动发工资，地产容量不自动给个人福利 |
| IND | 制造品/材料/科技交付订单与有限补库存 | 原料能源、物流按实际可用量；科技存量不当作销售收入 |
| SRV | 可交付居民服务、零售物流和政府采购 | 各服务地点/期间生效，不能仅按人口永久获得固定利润 |
| CHU | 有资金的宗教服务计划与经营服务需求 | 实际捐赠可支持岗位；无需强迫非营利部门先有正利润；招聘不增加信徒 |
| BNK | 金融服务工作量、已存在贷款管理与有资金的服务计划 | 贷款本金不作营业支持，放款资金与工资资金不能重复分配 |
| MAG | 教育/魔法/研究订单、已拨研究教学任务 | 按已有准入规则过滤申请；买入魔法资源或点数不增加员工 |
| GOV | 玩家/既有政府计划批准并拨款的人员数 | 不按盈利或私营订单裁减；保留其既有工资等级和真实政府付款 |

对混合型部门，先将经营任务和已拨公共任务换算到同一活动计划后统一计算，不能把同一员工在两个目标中算两次。没有定义的技能/法定资格不在本模型中伪造；已有准入限制必须作为撮合边的合法性输入，参考数值场景假定参与者均满足相应准入。

## 7. 劳动力进入、退出和转行

### 7.1 被动退出与待岗

冻结上一期就业E和本期目标T、K、H。先计算硬退出：

```text
exit_hard_i = max(0, E_i - H_i)
E_keep_i = E_i - exit_hard_i
excess_i = max(0, E_keep_i - T_i)
exit_soft_i = min(excess_i, floor(.10*E_keep_i + carry_exit_i))
E_base_i = E_keep_i - exit_soft_i
```

硬退出表示本月不能按正常有薪岗位继续录用，不等于抹除上月工资债务。必要的欠薪、停工、解约事件保留记录。软退出针对仍能发工资但需求或可持续条件下降的部门；剩余员工可有薪待岗，不假装都在有效生产。低吸引力本身不自动触发裁员。

### 7.2 可招聘空缺

```text
V_i = max(0, T_i - E_base_i)
hire_quota_i = min(V_i, floor(.10*max(E_base_i,20) + carry_hire_i))
```

20是新部门的招聘速度基准人数，不是免费人口、岗位或免工资额度；E=0且有资金和空缺时，默认每月最多招聘2人。上限和速度来自外部配置。裁员后T<=E_base的行业没有新增空缺，避免同月裁人又重新招同一类人。

### 7.3 先待业者，再在职转行

1. 待业池包含全部八群体失业劳动力及本轮退出者，不只h=0。
2. 在符合准入和有资金的空缺之间，先最大化待业者录用人数；同样录用人数下最大化吸引力收益。
3. 剩余空缺才对在职者开放。只当 `A_destination - A_origin > 5分` 才允许自愿转行；取等号不转。
4. 每个来源行业本月可转行人数不超过 `floor(.05*E_base + carry_switch)`；同一人在本月最多一次流动。
5. 在职者保留原岗位，只有获得目标行业录用后才离开；没有录用不先裸辞。低分导致自愿裸辞是可选后续玩法，本版不暗中添加。
6. 招聘容量使用本轮冻结空缺，转行新腾出的岗位到下月再开放，不做七行业循环抢人/同人多次跳槽。
7. 统一输出流动矩阵，一次更新所有行业就业。

撮合采用整数最小费用最大流（通俗比喻：在各行业名额限制下，先让最多的人找到工作，再把可选岗位尽量安排到更受欢迎处）。固定行业ID排序处理同分，不依赖字典顺序。可以按群体供给拆源节点，并删除不符合已有准入条件的边；未获录用的仍在原待业池。

```text
E_next_i = E_base_i + hires_from_U_i
           + sum_j switches_j_to_i - sum_j switches_i_to_j
U_next = U_before + sum_i exit_i - sum_i hires_from_U_i
sum_i E_next_i + U_next = F
```

容量K不因录用/离职直接增减；只有建筑、资金、原料等输入变化才重算。员工不足造成未实现产能，应反馈下一月真实收款，而不是即时降低自身K再反复自我惩罚。

### 7.4 整数与边界

招聘、软退出、转行各自保存0..1人的小数余量。没有相应空缺/退出差额/合法转行目的地时清空该项余量，不能囤积几年份额后瞬间爆发。例：1名员工、每月5%转行额度，持续有机会时20个月积累成1人。

在职转行严格要求吸引力提高；同一快照不会出现A→B→C→A的循环。分数门槛、评分平滑、速度限制共同减小月度抖动；不承诺外部环境剧变时永远无波动。

## 8. 居民群体与工资归属

采用**8×8汇总劳动力表**：8个居民归属群体为行，7个就业行业和待业为列。没有逐人对象、家谱或职业履历。

```text
X[h,i] = 归属群体h、实际在行业i工作的劳动力人数
U[h] = 归属群体h的待业劳动力
F[h] = sum_i X[h,i] + U[h]
sum_h F[h] = F；F[h] <= P[h]
E[i] = sum_h X[h,i]
sum_h P[h] = N
```

原金标准开局可用近似对角的X初始化，不改变总人数和工资。初始化各群体待业人数时，将全城U按各群体 `P[h]-sum_i X[h,i]` 的剩余人数比例，以受上界约束的最大余数法分配，再令 `F[h]=sum_i X[h,i]+U[h]`；不要求每个群体单独都满足固定55%劳动参与率。允许跨行业就业后，原来的 `P_i>=E_i` 仅对对角初始化成立，**通用硬约束应明确改为每行 `sum_i X[h,i]<=F[h]<=P[h]`**；不继续用同一行业标签把居民人数和雇员人数绑死。这是本文对V2.1群体接口的明确增补，不是静默改写。

员工转行只更新X对应两列；P[h]、家属归属、S[h]和资产所有权不自动变化。工资按实际雇主i→居民群体h发放；农业工资免税按就业行业i及收入性质判断，不按h永久免税。分红、租金仍按产权进入原群体。

被裁员工从X[h,i]进入U[h]；再就业从同一U[h]进入新X[h,j]。招聘不会把不参加劳动的家属变成工人。城际迁移仍由现有世界人口迁移处理，并另行转移其对应群体人口、劳动力和可携储蓄；不得与本城转行重复处理。

独立参考程序验证行业总量边界和转行矩阵，不假称已经实现X表的真实工资入账；正式接入需增加按h细分的撮合与账簿验收。

## 9. 时间顺序及与城市K/L的关系

### 9.1 月度边界

每个月先用上一月真实结果生成评分与经营计划，月初锁定已到账资金和必要投入，再一次撮合本月员工；员工只在最终岗位发一次工资、生产一次。不能先领旧岗位工资，再在新岗位同月领另一份正常全月工资。

```text
上一月账簿/发薪/环境 → 更新A，确定本月任务与预算
已完工建筑/已交付投入 → 当前J、J_cash、J_fin、J_input → K和T
退出/招聘/转行 → 冻结X、E和U → 本月真实工资 → 生产/市场/财务
本月结果 → 下月历史 → 城市K/L及世界人口迁移
```

当月涨薪先占用真实工资预算，吸引力随已兑现工资历史更新；如需展示新报价，作为“录用报价”单独显示，不提前冒充实际收入。突发停工/资金冻结立即收紧硬可支付边界，必要退出与欠付事件保留。

本版没有并行进程或嵌套月份循环。唯一主循环按世界月份推进；城市内七行业读取同一快照；唯一撮合器收集全部申请后统一出结果。未来即使并行算指标，也必须在共享库存/预算分配和统一撮合处同步，不能并行各自扣同一笔钱或抢同一批人。

### 9.2 城市层指标

- 城市K中的可持续岗位Jop改由 `sum_i K_industry_i` 提供；不能再把旧Jop和新K同时相加。
- 城市就业率仍用实际 `sum_i E_i/F`，而非K/F；有岗位没人来会体现在就业率。
- 保留现有城市K中的住房、持续粮食和安全约束，不额外把A乘到城市K上。
- 城市L继续用真实居民可支配收入和公共服务；不把行业A再加权塞进L，避免同一工资/安全反复加分。
- 行业K是岗位人数，城市K是可支撑人口人数，不能直接相加或比较为同一单位。

城市迁入者下个月参与岗位撮合，保持既有“同月不重复参与工资消费”的边界。

## 10. 配置、界面与可解释性

机器可读初值见 `行业双指标模型/parameters.json`。配置状态为design_reference_not_runtime，正式接入前不让现有程序误读为已启用规则。

| 参数 | 初值 | 含义 |
|---|---:|---|
| 储备摊用期 | 3月 | 无持续收入时不能永久用一次资金撑岗位 |
| 劳动产出指数 | .8 | 复用现有生产关系 |
| A维度权重 | 收入.60/稳定.25/环境.15 | 员工视角的工作质量 |
| 稳定性权重 | 按时率.60/缓冲.40 | 信用和抗短期波动 |
| 收入参考 | 工业税后82.8 CR、生活成本50 CR | 固定真实购买力锚点，不随本城高薪行业一起移动 |
| 评分更新权重 | .50 | 逐月吸收新信息 |
| 历史权重 | 新到旧.50/.30/.20 | 关注近月，保留近期记录 |
| 招聘/软退出/转行速度 | .10/.10/.05每月 | 三种不同调整速度 |
| 转行优势门槛 | 大于5分 | 防止微小差异来回跳槽 |
| 新部门招聘基准 | 20人 | 支持从0起步，每月初始最多2人 |

| 新雇主按时率先验 | .80 | 仅冷启动评价，不当作历史实测 |

内部初值的建议调试区间：储备期2—6月、招聘.05—.20、软退出.05—.15、转行.02—.08、门槛3—10分、评分更新.25—.75。它们是测试范围，不是对作者规则的新增硬限制。维度权重及其子权重必须非负、和为1；所有速率和质量比例在0..1，金额为非负整数分，工资/生活成本为正；NaN/Inf一律拒绝。

行业面板示例：

> 工业：容纳限度91人，当前60人；短板是持续工资支持。行业吸引力62.5分；收入30分、稳定25分、环境7.5分（环境暂无实测）。本月目标60人，暂不招聘。

可展开查看已建岗位100、当月工资可付100人、持续工资支持91人、原料可支持100人。玩家据此知道应增加真实订单/运营支持，还是扩建、补原料或改善待遇；不显示一串没有业务含义的乘数。

## 11. 数值例子与验证结果

### 11.1 复用七行业工资的吸引力基线

合成比较条件：生活成本50 CR；按时率1、现金缓冲至少3月、环境无数据按.5、没有额外岗位福利、无上一期评分。不是实际五城评分。

| 行业 | 税后劳动收入CR/月 | A |
|---|---:|---:|
| AGR | 60 | 48.5600 |
| IND | 82.8 | 62.5000 |
| SRV | 92 | 67.0601 |
| CHU | 69 | 54.6090 |
| BNK | 92 | 67.0601 |
| MAG | 82.8 | 62.5000 |
| GOV | 69 | 54.6090 |

这些分数是行业选择评分，无需和城市宜居度65—82使用同一目标区间。农业若真实提供岗位住房福利会改善分数；银行与服务工资相同不代表永远一样，实际发薪和环境可使其分化。

### 11.2 容纳限度例子

假设有100个真实岗位、单人工资90 CR、当月真实工资预算9000 CR、可重复支持11200 CR/月、必要非工资支出4000 CR/月、可动用储备3000 CR、原料充足：

```text
J_cash = 9000/90 = 100
J_fin = floor((11200-4000+3000/3)/90) = 91
J_input = 100
K_industry = 91
```

原料只够满负荷50%时，J_input=floor(100*.5^(1/.8))=42，K下降到42；资金仍够时人员逐步缩编或有薪待岗，不立即抹除员工。若本月工资预算只剩2700 CR且没有额外储备，硬上限只能30人，不能用评分或历史销售把工资补出来。

### 11.3 已执行的验证

运行：`python -m tools.model_design.validate_industry_labor`。

证据：`docs/04_验收记录/行业双指标模型验证-2026-10-15.json`。共33项定向/集合验证，其中包含500组随机七行业约束检查、100组2×2撮合穷举最优值对照。

覆盖了建筑/现金/投入边界、资源反推指数、无配方行业、无持续支持、名义同比缩放、真实福利、欠薪、高生活成本、工作安全、需求反推、无空缺不流动、先待业后转行、5分门槛、硬退出/软缩编、从0招聘、撮合不浪费可达名额、整数余量及非法输入。

固定环境120步实验：农业100人、服务50人、待业0；两行业各可容纳100、各目标100，吸引力20/95。服务在第14步达到100人，此后停在农业50/服务100，劳动力总数150不变；没有因为农业低分就自动清空农业。

这是**劳动力子模型在固定外部条件下的验证**，没有运行完整资金、商品、人口迁移世界，不能写成“游戏已通过120个月稳定性验收”。

## 12. 工程衔接与适用限制

| 位置 | 后续接入动作 | 完成标准 |
|---|---|---|
| states.py / 存档 | 添加历史、双指标、分项、目标、小数余量和X/U表 | 旧种子迁移不造人、不造钱，初值可追溯 |
| labor.py | 用统一流动撮合替代当前失真的岗位分配 | 逐群体/行业人数守恒、顺序无关、合法准入、各员工每月最多一次流动 |
| production.py | 用同一活动配方衔接投入上界和实际产出 | 原料和产出恒等式，资源短缺不重复乘罚 |
| ledger / payroll | 工资由雇主按X分配到居民群体 | 工资总额等于付款总额，农业免税按实际雇主，未支付保留欠付 |
| monthly_engine_full.py | 按第9节接入，移除原工资/岗位/供粮占位输入 | 真实状态驱动，没有“标记执行了”替代实际变化 |
| capacity / migration | Jop只汇总一次新K，人口迁移仍在世界层 | 本城转行与城际迁移分别守恒，无同月重复工资消费 |
| 订单/预算上游 | 分配并锁定现金、投入、招聘计划 | 七行业不重复认领库存或政府同一笔钱 |
| 正式验收 | 行业停工、欠薪恢复、订单增长/消失、跨城供给中断、公共预算变更及群体转行 | 双指标变化有真实原因；五城12/36/120月真实模拟另行完成 |

参考计算位于 `tools/model_design/industry_labor.py`，参数不硬编码在游戏模块；验证入口与生产代码分开。它验证数学和劳动力总量，**没有接管经营钱包、采购、自动扩建或完整群体税务**。

正式接入仍受前次完整性审计约束：当前市场清算、物业和守恒实现尚有问题，不能直接接上新指标就宣称经济闭环完成。没有数据的工作环境使用中性值并展示缺失；没有准入和培训设计时不能宣称已经模拟了现实职业资格。该限制不影响本次双指标模型的数学定义，但影响完整游戏的现实细节和数值校准。
