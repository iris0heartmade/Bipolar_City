## 1. 设计目标

**M27 = 让 NPC 城市之间产生自发的贸易流，呈现"活着的世界"。**

M26 让玩家能主动改变 NPC 友好度，但 NPC 城市之间是静态的（友好度固定 50）。M27 在 `WorldGame.advance_npc_only()` 后自动生成 NPC-NPC 月贸易流，让世界"自己动起来"。

视觉上，玩家在世界地图上看到 6 条 NPC-NPC 蓝色虚线（叠加在原橙色关系连线上），中段标注月贸易额数字。这是"活着的世界"的最直观信号。

## 2. 游戏体验：贸易流的可视化

玩家打开 `/world`，看到：

- **5 个城市节点**：4 NPC（绿/蓝/紫/棕）+ 1 玩家（金色）
- **10 条橙色关系连线**（C(5,2)=10）
- **6 条蓝色虚线**（仅 NPC-NPC 4 个城市之间，C(4,2)=6）
- **每条虚线中段**显示月贸易额（334、284、393、112、137 等数字）

推进 1 月后：
- 虚线仍在（贸易流持续）
- NPC-NPC 友好度自然增长（+1/月，因为贸易产生 +1 友好度信号）
- 玩家-NPC 友好度不变（玩家需要 M26 外交行动才能改变）

玩家点了 NPC 城市（不在玩家下台状态）后，仍可发起 M26 外交行动；这次行动因为友好度更高，可见等级可能升级（如 Lv.2 友好 → Lv.3 盟友），解锁更多字段。

## 3. 贸易流公式

```
volume_cr = clamp(
    base × (friendly / 100) × distance_factor,
    min_volume,
    max_volume
)

distance_factor = 1.0 / (1 + distance / divisor)
```

**参数（`data/npc_trade_routes.json`）**：

| 参数 | 值 | 含义 |
|---|---|---|
| `base_volume_per_month_cr` | 1000 | 满友好度零距离时的月贸易额 |
| `friendliness_threshold` | 30 | 低于此阈值无贸易 |
| `distance_factor_divisor` | 100 | 距离因子除数（distance=100 → 距离因子=0.5） |
| `trade_friendliness_delta_per_month` | 1 | 双方友好度月增 |
| `min_volume_per_month_cr` | 100 | 钳位下限 |
| `max_volume_per_month_cr` | 5000 | 钳位上限 |

**示例**：

- 友好度=50，距离=100（城市间典型距离）：volume = 1000 × 0.5 × 0.5 = 250 CR
- 友好度=100，距离=0：volume = 1000 × 1.0 × 1.0 = 1000 CR
- 友好度=30，距离=1000（极远）：volume = 1000 × 0.3 × 0.0909 = 27 → 钳到 100 CR
- 友好度=100，距离=0：volume = 1000（不超过 5000）

## 4. 友好度阈值与钳位

### 4.1 友好度阈值 30

`friendliness_threshold=30` 决定哪些 NPC-NPC 对产生贸易。

- 友好度 ≥ 30 → 产生贸易流
- 友好度 < 30 → 无贸易流（双方"未在单月内交易"）

**初始友好度 50 全通过**，所以 M27 默认所有 NPC-NPC 对都有贸易。

### 4.2 友好度月增 +1

`trade_friendliness_delta_per_month=1`，双方友好度各自 +1/月。

**效果**：初始 50 → 3 月后 53 → 半年后 56 → 100% 需要约 50 个月才能到上限（被钳到 100）。

### 4.3 玩家-NPC 友好度不变

M27 **只处理 NPC-NPC 之间**的自动贸易流。玩家-NPC 友好度需要玩家主动发起 M26 外交行动才能变化（trade_agreement +1/月 或 aid / immigration_open / statement 等）。

这是设计有意为之的：玩家是"主角"，NPC 是"盟友/对手"，NPC-NPC 是"世界"。

### 5.3 NpcTradeRouter

```python
class NpcTradeRouter:
    def monthly_flow(self, city_a, city_b, distance_units, friendliness) -> NpcTradeFlow | None:
        if friendliness < self.config.friendliness_threshold:
            return None
        distance_factor = self.compute_distance_factor(distance_units)
        raw = self.config.base_volume_per_month_cr * (friendliness / 100.0) * distance_factor
        volume = max(self.config.min_volume_per_month_cr,
                     min(self.config.max_volume_per_month_cr, raw))
        return NpcTradeFlow(
            city_a=city_a, city_b=city_b, month=0,
            volume_cr=round(volume, 2),
            friendliness_delta_per_side=round(self.config.trade_friendliness_delta_per_month),
        )

    def route_all(self, npc_ids, positions, friendly_lookup, current_month) -> list:
        flows = []
        for i, a in enumerate(npc_ids):
            for b in npc_ids[i + 1:]:
                distance = euclidean_distance(positions[a], positions[b])
                friendliness = friendly_lookup(a, b)
                flow = self.monthly_flow(a, b, distance, friendliness)
                if flow:
                    flow.month = current_month
                    flows.append(flow)
        return flows
```

### 5.4 WorldGame 集成

```python
def advance_npc_only(self, months: int = 1) -> 'WorldGame':
    new_game = deepcopy(self)
    new_game.world = replace(self.world, month=self.world.month + months)
    new_game.npc_city = self.npc_city.advance(months=months)
    # M27：NPC-NPC 贸易流（按月生成 + 友好度互调）
    new_game._apply_monthly_trade_routes()
    return new_game

def _apply_monthly_trade_routes(self):
    router = NpcTradeRouter()
    npc_ids = [c.id for c in self.world.cities if not c.is_player]
    positions = {c.id: (c.x, c.y) for c in self.world.cities}
    def friendly(a, b): return self.diplomacy.get_relation(a, b).friendliness
    current_month = self.world.month
    flows = router.route_all(npc_ids, positions, friendly, current_month)
    for flow in flows:
        self.diplomacy.record_trade_flow(flow)
```

## 6. 核心约束：叙事优先，不破坏守恒

**M27 与 M26 一致：不实际发生跨城现金流。**

理由：

1. **跨城现金流破坏守恒**：IndustryEconomy 的 `assert_invariants()` 校验 `cash + OCEAN == initial_total_cash`。强行从玩家城市转给 NPC 城市，cash 总和会变化，守恒失效。
2. **NPC 城市有自己的 IndustryEconomy 实例**：5 NPC 各持一套 cash / employment / last_report。NPC-NPC 转账需要 6 个账本的资金流，引入复杂的"交易双方匹配"逻辑。
3. **设计意图**：M27 是**关系层扩展**（"活着的世界"），不是经济层扩展。真实贸易留给 M28（行业情报）或后续专门的"贸易结算"模块。

代价：**玩家看不到真实 NPC 经济被贸易改变**。但友好度变化（+1/月）作为"贸易让双方更友好"的叙事信号足够直观。

后续路线：M27.1 引入 `IndustryEconomy.transfer_to_npc(target_city_id, cash_cr)` 方法，绕过守恒校验（NPC 现金是虚拟记账，玩家现金是真实扣款）；trade flow 此时升级为"有 trade volume 也有 cash delta"。

## 7. 边界与限制

- **友好度阈值 30**：低于阈值无贸易。这是设计有意为之（"陌生人不会做生意"）。
- **min/max volume 钳位**：避免贸易额 0（极端距离）或天文数字（满友好度零距离）。
- **距离用欧式距离**（viewBox 坐标）：不是真实地理距离。这是为简化而设计；M28 可替换为真实距离矩阵（data/world_map.json 中已有）。
- **玩家-NPC 不参与自动贸易**：玩家必须主动发起 M26 外交行动。
- **每月 1 次推进**：每月生成一次 trade flow（不区分多个月合并）；M27.1 可改为"3 月累积贸易流"。
- **存档兼容**：`npc_trade_routes` 不持久化（每次重新计算）；trade flow 的"持久化效果"通过 Diplomacy 友好度保留。

## 9. 后续路线

### M27.1：真实贸易转账

- 引入 `IndustryEconomy.transfer_to_npc(target_city_id, cash_cr)` 方法
- 玩家援助/贸易**实际扣款**（破坏 `cash + OCEAN == initial_total_cash`，需引入"transfer exception"路径）
- 守恒路径：玩家现金减 → OCEAN 池减 + 1（成对记账）→ NPC 现金加（虚拟）

### M28：行业情报

- 玩家向友好度 ≥ 3（盟友级）的 NPC 城市派遣"商业间谍"
- 获取完整 last_report（不脱敏）
- 这是 M25 后台设计中的"信息差"玩法扩展

### M28.1：NPC 城市详细月报

- M25 的脱敏是按可见等级过滤
- M28.1 把"完整月报"作为"盟友级情报"，可通过 M26 友好度升级解锁
- 玩家可对比 NPC 月报与玩家月报，发现"什么行业 NPC 走偏"

### M29：世界事件

- 随机世界事件（瘟疫/丰收/战争）按距离影响周边城市友好度+经济指标
- 事件来自 WorldGame.world.month 推进时触发

### M30：长期政治

- NPC 城市联盟/敌对关系，玩家可加入任一阵营
- 影响全局贸易格局与外交决策
