## 1. 来源、统一决策与当前差距

来源编号：**G**＝[原游戏设计总纲](../01_原始输入/bipole世界观下开罗式模拟经营游戏的设计稿.txt)，引用 Q 编号或章节；**E**＝[城市经济输入 V1.0](../01_原始输入/Bipole_城市经济系统开发输入_V1.0.txt)，引用章节；**U**＝本轮用户最新明确回复。

| 决策 | 原内容差异 | 统一开发要求 | 依据/状态 |
|---|---|---|---|
| DEC-01 住宅投资路径 | G Q51/Q53 玩家直建；E §0/5 私人开发为主 | 政府直建或规划住宅地让开发商建设，均为玩家选择；用时、花费、效果有受控随机差异 | U 最新确认，覆盖路径冲突 |
| DEC-02 产权与付款人 | 私人产权为主不代表每栋楼由政府免费出资 | 路径决定投资与施工付款方，产权决定租金/维护/税；公共住房和政府售房保留 | G Q52—54、E §0/5 |
| DEC-03 地图 | G 64×64 为建议；当前 28×28；E 默认 64×64 | 新校准场景默认 64×64、20m/格；保留旧模板，不拉伸存档 | E §0.3；实施约定 |
| DEC-04 时钟 | 原型日施工，E 经济月 tick | 日时钟推动施工；每 30 日触发唯一月结算；12 月/年，暂停停止时间 | G Q2/29/30、E §0/10 |
| DEC-05 科技 | G 确认市政/工业/魔法；E §14 扩展建议技术/魔法/社会制度 | 保留 G 三树；社会制度改革作为政治机制，不静默更换科技树 | G Q22 是明确选择；E 为扩展建议 |
| DEC-06 货币 | 原型标银镑，E 使用 CR | 新经济基准用 CR、100 分/CR；旧银镑档保留单位，不默认 1:1 换币 | E §0.3；兼容细节为实施约定 |
| DEC-07 群体与路径 | 群体人口，不逐人通勤；E 要真实最短路 | 按住宅区/群体与企业算路程，行人车辆仍为演出 | G Q4/14/48/49、E §4/5 |
| DEC-08 国家 | 世界观允许有限冲突，但不能征服 | 统一议会、任命市长、不吞并城市、不允许玩家主动开战，早期缓做政治 | G Q7/43—45、E §0/14 |
| DEC-09 宗教 | 原稿未详细定义，E 明确轻量方案 | 四个常规经济效应＋五档政策＋一个聚合账户，不扩成教会经营 | E §6 |
| DEC-10 阶段编号 | 原型、G 和 E 的 M0/M1/M2 不是同一范围 | 现行开发只用 P00—P10，旧方案标归档 | [主计划](../02_开发规划/分阶段开发计划.md) |
| DEC-11 初始现金/细分分配 | E 给政府和教会现金，但未给每家企业、家庭现金及全部交易矩阵 | 开发前显式补校准配置，预算足额才能执行基准；不能硬写最终报表 | E §11/12；实施约定 |
| DEC-12 结算周期 | 原型为日步长推进＋月底做一次财政结算；新引擎为纯月结（每月 30 号唯一结算） | 经济结算统一采用新引擎的月结，原型那套「每天按人口加一次钱、月底再结一次」不再保留；日时钟只推动施工等非经济进度 | U 最新确认 |

## 2. 系统树、单位和结算契约

### 术语速查

| 术语 | 通俗说明 |
|---|---|
| 状态 State | 城市此刻的钱、人口、楼和合同等全部事实 |
| 快照 Snapshot | 某个时点的完整只读照片，显示与保存使用它 |
| 存量 stock / 流量 flow | 月末还剩多少 / 这一月发生多少，不能混成同一个数 |
| 交易 Transaction | 一笔有付款方和收款方的搬钱记录 |
| 预留 reservation | 钱仍在钱包，但已答应给某份合同使用 |
| 幂等 idempotency | 重复按确认，同一件事只办一次 |
| 原子提交 atomic commit | 整月操作全部成功才落账，否则保持旧世界 |
| 行业聚合 SectorAggregate | 初期用一个行业代表账户代管多家相似企业 |
| CPI 物价指数 | 用同一篮商品比较整体价格变化 |
| GVA 经济增加值 | 扣去重复的中间购销后，这座城真正新增的生产价值 |
| 折旧 depreciation | 资产磨损的账面成本，不是又付一次现金 |
| 资本支出 capex | 购买设备、建设设施等长期资产的钱 |

### 2.1 组合与调用关系

以下为组合/调用树，不强制复杂继承体系：

```text
Web 展示与输入（M20，只读快照/发送意图）
└─ CommandService（校验权限、版本、重复请求）
   ├─ World / City / Config / Clock / RNG（M01）
   ├─ 地块、报价、建设、产权（M04—05）
   └─ MonthlySimulation（唯一经济调度入口）
      ├─ 空间环境：道路/设施/风险/邻接（M08、M12—15）
      ├─ 经济主体：居民/雇主/房东/市场（M03、M05—07）
      ├─ 国家市场：库存/交易/NPC 城市（M11）
      ├─ 财政与债务：税费/采购/工资/贷款（M09—10）
      ├─ TransactionQueue → Settlement → Journal（M02）
      └─ 报告、下一期目标、科技/人物/事件（M16—19）
         └─ Snapshot + Save + AccountingAssertions（M21—22）
```

### 2.2 强制类型、单位和实体边界

| 对象 | 关键字段/约束 |
|---|---|
| World/City | 世界/城市 ID、`player_city_id`、月序号、日历、种子、版本、政策；多城使用同一连续时间 |
| Account | `account_id`、主体/城市、货币代码、整数现金分、预留分；可用钱＝现金－预留，不能另把预留加回全城现金 |
| HouseholdCohort | 人口、户数、收入层、技能、就业、钱包、预算/储蓄、信徒人数；职业和房产身份不是额外人口 |
| PrivateFirm / SectorAggregate | 行业、场所、钱包、资本产能、技能岗位、订单、实际支付工资/租金、成本、折旧、利润、税、分红、投资 |
| Property | 套数、产权份额/所有者引用、自住/出租/待售/空置、实际入住、评估值、维护与租金合同 |
| DevelopmentQuote / Contract | 路径、地块、投资方、付款方、成本/工期/品质/维护样本、报价键、版本、确认预算与履约状态 |
| PublicFacility | 位置、岗位、工资、服务容量、采购、覆盖；政府/企业付款来源明确 |
| ChurchAggregate | 信徒人数/比例、现金、实际奉献、向市政捐赠、收到市政补贴、政策与冷却；不模拟独立经营 NPC |
| LoanAccount | 借款人/贷款人、本金、月利率、宽限/到期、摊还计划、欠付/违约；本金不是收入/费用 |
| Inventory/Shipment | 资源、单位、数量、生产/消费/进出口/损耗、预留/在途、路线、对手交易引用 |
| MonthReport | 月份/单位/来源；就业、工资、收入、销量/利润/GVA、财税/融资、库存/服务/风险、账户残差 |

金额只用整数分或 Decimal；现金最终强制量化到分。税率/因子可用定点或 Decimal；距离选择权重可用有限浮点，但不得将其用于累计现金。数量用明确的整数/定点吨数/箱数，统一舍入与余量归属。

### 2.3 月度顺序与循环边界

以 E §10 为统一顺序：

| 步 | 行为 | 时点约束 |
|---|---|---|
| 01 | 克隆上期状态、完工、迁徙、已生效政策、外部报价 | 不重生成整张地图；迁徙基于上期已知条件 |
| 02 | 道路最短路/设施/魔物风险缓存 | 结构改变才失效重算 |
| 03 | 岗位匹配与当期合同工资 | 不先给居民增加钱包 |
| 04 | 从上期收入与现有储蓄设消费上限、预留必要支出 | 没钱不能预支当期未来营业额 |
| 05—06 | 采购、库存预留、有效产能和服务容量 | 无煤/人员/值守就不能满产 |
| 07 | 分配家庭/企业/资本/市政/旅游/贸易订单 | 供需不足最多三轮重分配 |
| 08 | 清算已接受的实际买卖、扣库存、记收入/成本 | 每笔付款唯一来源 ID |
| 09—10 | 工资、租金、规费、企业税、分红、房东维护 | 股息从税后利润与可用现金中支付 |
| 11—12 | 公共工资、所得/房产税、救济、教会、市政、贷款 | 08 已支付的采购/建设不重付；先预留必要政府支出 |
| 13—14 | 下期收入/价格/工资/投资/退出，信仰、教育、自然人口与稳定冲击 | 新收入主要影响下期购买预算；自然变动单独归因 |
| 15 | 会计断言、报告与状态提交 | 所有阶段通过才提交新月；保存恢复不重复本月 |

**循环约束：** 一个日时钟、一个月结算入口；订单重分配为月内部最多 3 轮；企业/片区/NPC 循环只生成计划或义务，不独自改全局时钟/提交第二份月报。早期使用单进程串行事务，不引入多进程；未来并行可只做只读计算，按稳定顺序汇入同一清算入口。加载、关闭服务、模拟异常必须停止旧时钟/待提交事务；画面渲染循环不生成经济收入。

### 3.3 必须显式处理的校准差异

1. E §11 的分红率 `0.4288 × 37312 = 15999.3856`，量化后 15999.39，不能同时精确满足首月 16000 的表。**实施约定：参考 fixture 用有理数 `16000/37312` 表示基准派息比例**，从真实税后利润计算；普通演化配置可用约 0.4288，但要相应重算预期。不是强行改企业/月报余额。
2. E §6.3 的教会简式没有写入 §6.2 官方扶持收入。完整式应为：`教会期末＝期初＋居民奉献＋市政扶持−向市政捐赠`。中立基准扶持为 0，不改变 +840。
3. 基准首月使用**月初**信仰 0.55 计算税、工资/工时和捐赠；中立政策月底按公式慢变为 0.5497，影响下一月。报告分开保存期初/期末信仰，不能把月底值倒套首月 5505/660。
4. 产能 425000、80% 利用率是校准选择。若加入基准安全/技能损失，应重归一化 K，不在原 80% 上重复扣同一损失。宗教工时归一化因子可在信仰低于参考值时略大于 1，不能无差别套所有因子 `[0,1]` 截断。
5. 期初各行业/家庭现金、全部企业间交易矩阵、技能结构、贷款宽限后摊还期限并未全部给出。配置必须注明这些是校准假设；没有期初流动性就不运行真实付款，不能用未到账工资虚构预算。
6. 本轮只做了源数据算术核对：合计与 +27100/211900 等式成立；这不证明未来交易引擎通过。原文中的 `[PASS]` 是输入书标记，不是当前代码的测试结果。

## M01 世界、配置、时钟与种子

**阶段/来源：** P00 起；G Q2/25/27/30/59/60、E §0/10/11。复用 `core/clock.py`、`model/world.py`，新增世界/城市/模型版本与配置校验。

- **开发要求：** 世界共用日历；月度经济仅在月界运行；施工按日或固定子步推进。暂停可以规划，不能施工/产生月收入。0.5×/1×/2×改变现实节奏，不改变一月公式。
- **三层周期：** 月（经济结算，每月第 30 日一次）／季（日常议会与政策窗口，每 3 月）／年（年度报告、目标调整、借款额度重估，每 12 月），另有约四年任期考核与二十年评价。依据 G Q24/Q30/§9.2、E §7.3；节律数据见 `data/economy/calendar_v1.json`。第 1 月不触发季度或年度事件，保证首月基准不被污染。
- **无季节系统：** 原始输入未提出春夏秋冬，本版不发明季节。若将来引入，须单独校准产能、燃料需求与消费篮子，并重新验证首月基准，不得在现有 80% 利用率上重复扣减。
- **数据：** `world_seed`、`current_month`、日偏移、`revision`、`schema_version`、`economy_model_version`、`config_version`、城市 ID/模板、RNG（通俗比喻：可保存的随机抽签序列）状态。
- **接口：** `advance_time` 驱动施工/月界；`simulate_month` 返回新状态、交易、月报和事件；同一世界/月只能提交一次。
- **设计细节：** 随机流按地图、报价、NPC、事件分域，防止动画/鼠标预览消耗经济随机数。使用稳定摘要或显式流，禁止用跨进程不稳定的语言默认 `hash()` 当种子。
- **界面：** 暂停/倍率/月推进、当年月份与结算忙碌状态。避免用户连点造成两次结算。
- **验收：** 同种子配置结果一致，暂停不变，丢帧不改变经济，保存后继续的随机轨迹一致；模拟异常不提交半月状态。

## M02 账户、交易、清算与守恒

**阶段/来源：** P01 核心；E §0.2/3/10/12/15。新增 `accounts.py`、`transactions.py`、`settlement.py`、`accounting.py`。

**交易字段：** `id, month, from_account, to_account, amount_cents, currency, category, source_ref, commodity_id?, qty?, status`。义务（通俗比喻：待支付账单）与已付款凭证分开；报表只将已清交易计入实际收入。

1. 双边内部转账同时减付款方、加收款方；外部付款以外部节点标记。初始化资产/期初现金是存量，不计首月收入。
2. 拆订单时先预留钱/库存，量化数量后统一清算；预留只是余额的受限部分，不额外记一份现金。
3. 同一 `source_ref + month + payment_part` 幂等；购买阶段与财政阶段可引用同一义务，不生成重复付款。
4. 余额不足时按类别缩单、延期、欠薪/欠租或违约，禁止无限透支。先锁定必要工资/合同支出，股息不能抢占工资资金。
5. 金额分配的舍入余数按稳定 ID/约定分摊；残差可解释，不能月末创造“神秘调整收入”补账。
6. 账户清算与库存/产权转移须同一原子提交。付款失败则库存/房屋不转移。
7. 房东子账户若拆开，必须从家庭主钱包中划出，合并现金只计叶子钱包；若不拆，租金直接付家庭业主，不能同时给房东镜像和家庭各加一次。
8. 月初开账余额须在本月第一笔玩家/系统付款前保存。日间发生的施工付款、放款、购房等也纳入本月交易日志；月界不能把已付款后的钱包当期初却再统计这些交易，否则月度守恒会漏算或双算。

**断言：** `各本地叶子钱包 Δcash 合计 = 与非本地账户实际净收付款`；多城内部款只改城别余额，不改世界内部钱包合计。贷款、移民自带资金、外来投资也列边界流，不能遗漏。

**禁止：** 营业额当新增钱；库存估值/地价直接加余额；房东身份加人口；借款当利润；用固定最终 517/27100 写结果。

**界面/验收：** 一笔流水可追溯对手和源合同；重复、拒付、部分支付、月回滚、存档幂等及闭城无外部流测试通过。

## M03 人口、家庭、劳动力与迁徙

**阶段/来源：** P03；G Q4/32/36/38/51、E §1/2/4/5。新增 `households.py`、`labor.py`，替换简单总人口岗位判断。

- **分群：** 住宅块＋收入层＋basic/skilled/professional/mage 技能；以家庭户数、成员人数和就业结构聚合。业主/商人/魔法师身份可重叠，但人口与雇佣不重叠计数。
- **恒等式：** 就业＋失业＋非劳动力＝总人口；劳动力＝就业＋失业；每个合同岗位必须绑定可用群体劳动者。
- **收入：** 工资由企业/政府，股息由企业税后现金，租金由租户/企业；社会救济由市政。报告区分全体居民人均收入与就业者平均工资。
- **招聘：** 按技能需求、通勤、工资与岗位匹配；同一群体人数录用后减少剩余供给；魔法适性与专业训练分别记录。
- **迁徙：** `U=0.30*真实可支配收入−0.25*住房负担−0.15*通勤+0.15*服务−0.15*危险`，各指数先归一化。普通净迁徙最多 1%/月，不能沿用原型固定 14 人对所有人口规模。
- **迁徙钱与信仰：** 居民自带余款由外部/原城市转入；迁出带走现金与结构。按实际人数重算信徒，不能只改比例。自然变动另记来源；空城恢复若要突破普通上限必须通过显式安置事件，不能隐藏豁免。
- **边界：** 初版不逐人年龄队列；特殊角色只是群体中有档案的子集，不能额外凭空增加 15—30 人。
- **界面/验收：** 人口、劳动力、失业率、收入层/住房负担与迁徙原因可解释；不足岗位不代表所有儿童必须离城；贫困预算和欠薪导致后期需求实际减少。

## M04 地图、用地、建造与随机报价

**阶段/来源：** P04；U、G Q15/19/20/28/29/59/60、E §0/5。复用占地/旋转，新增 `plots.py`、`development.py`、`quotes.py`、`developers.py`。

### 双路径选择

| 项目 | 政府直建 | 规划住宅地、开发商建设 |
|---|---|---|
| 玩家操作 | 指定住宅、位置、朝向、用途，申请直建报价 | 规划住宅地与开发限制，允许合格开发商报价/投资 |
| 实际建设付款 | 市政预算或获批市政贷款，付给施工/材料提供者 | 开发商/投资账户或获批私人贷款，付施工/材料提供者 |
| 市政费用 | 实际直建成本、道路/公共配套和持有维护 | 明示的规划、道路/配套、已批准补贴；不默认付全楼费用 |
| 产权结果 | 公房/保障房或真实出售；已售部分转私人 | 开发商建成后出售或出租给居民/投资者，政府不能自动收全部房款/租金 |
| 速度与效果 | 使用政府施工配置与报价样本 | 使用开发商能力、市场与报价样本；不是保证永远更快更便宜 |
| 无钱/无人报价 | 预算不足拒绝确认或按合同挂起 | 地块保持待开发，显示原因，不自动生成免费楼 |

### 受控随机差异

- **字段：** `cost_multiplier`、`duration_multiplier`、`quality_delta`、`maintenance_multiplier`；建成效果先限于居住品质和维护/服务性能，不随机直接增加市政收入。户数/占地按建筑定义固定，若以后允许容量变体需独立审查空间约束。
- **配置：** 两条路径分别有 min/max、抽样分布、开发商能力条件和版本。数值区间属于 P00/P04 校准项；本文件不把未实测百分比写成真实效率收益。
- **计算：** 成本＝基础工程价×报价成本因子，量化到分；施工天数＝基准日数×工期因子，至少 1 日；品质/维护效果在配置界内。政府和私人都产生有付款人的施工义务。
- **稳定键：** 世界/城市种子＋地块稳定 ID＋建筑方案＋投资路径＋报价周期＋报价配置版本。朝向对空间检查有效，但不能仅靠旋转刷重新抽签；预览/取消重放保持原报价。
- **锁定：** 确认前并排显示市政支出、开发方投资、日数、品质/维护结果与未确定的事件风险；确认后保存样本及合同，不在竣工/读档时重抽。新月份市场报价可变化，已签合同不随刷新变动。
- **施工付款时点：** 批准先形成预算承诺；实际预付款/里程碑款/完工款按合同执行。预付款是预付资产，不等于已交付住房的营业额或当月 GVA；同一工程最终交付时不得再收一遍已付预款。参考月只计已实际交付的资本品，未完工项目另列在建/预付存量。
- **风险：** 施工追加成本须有真实事件/合同条款与最大承诺额度；资金不足停工或补批，不默默穿透钱包。取消费用/可退预留以合同为准，不能建/拆/取消套利。

**状态机：** 规划/免费蓝图 → 可报价/等待开发 → 已承诺预算 → 待施工 → 施工中 → 竣工；不足条件可停工/撤销，必须释放对应预留且保留已实际支出。

**空间约束：** 整数多格占地、四向入口、河流/道路/已有占地不叠加，入口连到有效道路；固定模板与少量程序初始建筑，扩张必须邻接已解锁片区。已有城镇不是白地开局。

**验收：** 双路径的 UI、报价、付款、进度、产权一致；同格重放/旋转/读档不能刷随机样本；私人资金不足不扣市政全额；确认请求重发不重复收费；任何路径不得抢占现有住宅/道路格。

## M05 住宅、产权、租赁与开发商

**阶段/来源：** P02 基准房东账户，P04 完整；G Q51—55、E §2.1/5.1。

- **住房对象：** 按套/户管理，居民按人汇总。产权与入住分离；每套有主人、租户/自住/空置/待售状态，可聚合相同合同。产权份额只用于确有混合所有权的楼，不把整个小区都贴“公有”。
- **开发商：** 有钱包和收益预期，根据已规划地块、道路、空置率、租售回报、造价与融资决定是否投资。开发角色可挂在既有企业/投资主体，不为了身份再增加人口；参考六行业场景不凭空追加第七套营业额。
- **租房：** 私人出租房已竣工、合法、有可承担租金的租户即提供可入住容量；不能将“未售”一律等同“不可租住”。公房、待售未出租、自住房分别统计。
- **租金：** `rent_next=rent_now*(1+clamp(0.20*(occupancy−0.93),−0.03,+0.03))`。健康空置约 5%—8%是校准目标，不保证每栋固定入住率。
- **收付：** 居民租金付真正业主；商业物业租金由企业付业主；业主付维修企业、税费和利息。自住无现金租金；V1 不计自有住房虚拟租金。
- **出售：** 买方已有现金/获批按揭真实付款给卖方，产权/资产同时转移。政府售房收入只来自市政真实持有库存；私人开发商销售不自动变成政府卖房收入。
- **维护/税：** 谁持有谁负担约定成本与房产税，私人维护不能当市政免费承担；已售单位不得继续收市政租金。
- **欠租/搬迁：** 钱不足形成实际未收/欠租与住房压力，不创造收入。转公共出租/出售/拆除要处理在住合同与替代房，不强制无预警清空。
- **价格/估值：** 资产价格变化只更新评估/抵押参考，现金只有成交或税款时变化。待售成本、评估值和余额分别显示。
- **界面/验收：** 显示总套数、出租、自住、空置、待售、租售报价、付款方/业主、实际维护；600 户×47＝28200，750 入住＋50 空置＝800；租金双边匹配、私人/公有资金分开，重复出售/退款不可增钱。

## M06 企业、生产、工资与 NPC 决策

**阶段/来源：** P02 聚合、P05 逐店；G Q5/12/16/20/21/24、E §2.2/4/9。

**状态：** 行业、地块/场所、钱包、资本与有效产能、技能岗位、工资合同、物资/订单、实际销量、营业额、投入、租金、折旧、规费、税前/后利润、股息、资本投资、连续困难月数。

六行业是初始校准分类，不限制全部后期产业。地理改变比较成本和优势，不把城市硬锁为唯一产业；魔法相关产业可随技术与材料条件扩展，不凭地名强制禁止。

1. `Qcap=K*F_labor*F_skill*F_resource*F_service*F_safety*F_worktime`。劳动因子 `min(1,(实际/所需)^0.8)`，技能因子 `(有效/要求)^0.3` 限 0.65—1；资源与服务不足先约束供给。K 是单位数，不能把涨价当增加产能。
2. 税前利润＝实际收入−采购/物流等现金成本−工资−商业租金−折旧−规费；利润税按每个纳税主体 `max(0,利润)*税率`，不能亏损产生负税或简单用跨企业亏损抵掉别家税基。
3. 分红从税后利润与可用现金取较小值；留存会计利润与现金变化不同。现金只减真正支付的投入/工资/租金/税/股息/资本/利息，本金另记融资；折旧不能再减钱包。
4. 工资目标按 CPI、技能紧张度、宗教工资保留变化：指数分别 0.70、0.12；相对基准 `theta_ref` 和 `f_ref=0.55` 归一化，目标收敛 25%，普通月 ±3%，不低于法定最低工资。技能工资保留系数见 M14。
5. 开业：规划/道路合法、预期利润率 >6%、初期资金覆盖 1.5 月固定支出，建议预期回本 6—24 月；无融资不凭空开店。新店抢走旧店客流并不必然增加全城消费。
6. 扩张：订单、现金、工人可得，前 3 月利用率 >85%；买资本品真实支付卖方。预期用过去 3 月销量平滑，不读未来事件结局。
7. 退出：连续 3 月无法支付必要费用或连续 6 月亏损触发处置，保留欠付/银行债务与可恢复提示，不一次坏月全城清盘。

**界面/验收：** 企业页可看营业额、成本、利润、现金、岗位、订单与退出原因；全城 86 家的拆分首月能回聚到六行业基准；价格上调不等于产量上调；亏损、欠薪、扩张/退出都改变真实账户。

## M07 消费、市场、订单与价格

**阶段/来源：** P02/P03/P04/P05；E §4.3—4.4/8.3。

- **预算：** 来自上期可支配收入、可动用储蓄和实际获批信贷，预留计划储蓄/房租等；最终上限不超过已有可用资金。未花预算留在家庭钱包，不能当作商户收入。
- **篮子：** 食品、燃料/基本品、衣物、生活服务、文化、客运；低收入食品占全部支出 55%—65%为建议，注意包含房租的分母与纯商品消费分母不同。全城参考食品 71000/商品服务 119000 不套每个家庭。
- **选择：** 片区到商户的实际路网时间 `t_zi`；`V=0.40*质量−1.10*(价格/类参考价)−0.07*分钟`，`weight=exp(V−maxV)`；不可达商户不获普通本地订单。
- **外部选项：** 外购实际向外部账户付款，并记边界流；未消费不扣款；不能把 `weight_outside` 对应预算凭空销掉。
- **订单：** 家庭、企业中间品、资本、市政、旅游、出口均有付款预算与用途分类。商户供给不足最多 3 轮重分配，最终实际成交＝可交付供给与已付/可清算订单的较小值。
- **价格：** `P_next=P*(1+clamp(0.08*log((需求+eps)/(供给+eps)),−0.05,+0.05))`，缺货是未交订单，不按高价伪装成已成交。普通/月和事件豁免分开记录。
- **CPI：** 用已成交/稳定参考篮子构建物价指数，初始 1.000；缺货无成交的类目用有记录的回退参考，禁止 NaN。
- **界面/验收：** 显示预算、实际消费、外购、缺货/剩余储蓄；同预算新道路只重分份额，不凭空增加总消费；涨价导致销量与份额变化，供不应求不能重复卖库存。

## M08 道路、物流与公共交通

**阶段/来源：** P04/P06，公共交通深化 P09 后；G Q6/47—50、E §4.5。

- **道路图：** 整数格连通，地方路/铺装/干道具有速度、容量、费用。20m/格；步行 1.1m/s≈0.303 分/格，马车 3m/s≈0.111 分/格；类型系数 0.75/1/1.30 是校准配置。
- **最短路：** 按片区入口、企业入口、公共设施算共享路径缓存；与地块旋转入口一致，禁止使用屏幕直线距离代替实际路线。
- **负荷：** 区域客流与货流汇总，时间因子 `1+0.15*(flow/capacity)^4`，早期可分档近似。容量必须正数，断路/闭线有明确结果。
- **物流成本：** 货量×路由单位成本×拥堵，加明确费用；付给物流企业/外部承运者，不能只有卖家扣成本却无人收款。
- **投资：** 本地路网/站场由地方建设付款；全国干线按固定节点共投/中央审批，不每个小货站都立法。线路改造不能改变全国城市领土归属。
- **公交：** 站点与线路计算覆盖、客运需求分担，不模拟逐乘客路径；不能把客运改善直接加到货运吨数。
- **界面/验收：** 连接/行程/负荷/费用图层可看原因；修路固定消费预算场景全城钱不增；无路商户与驻地覆盖失效；道路维护 2200 只计一次；运输不超站场/线路容量。

## M09 市政财政、税制与公共企业

**阶段/来源：** P02/P05；G Q8/12/53—55、E §2.4/7。

| 政策 | 起点/允许范围 | 调整约束 |
|---|---|---|
| 所得税 | 8%，0%—20% | 每次最多 ±2 个百分点，6 月冷却 |
| 正利润税 | 12%，0%—25% | 每次最多 ±3 个百分点；统一政策冷却由配置明确，初版采用 6 月实施约定 |
| 房产税/月 | 0.12%，0.03%—0.25% | 按真实评估和宗教减免，冷却同政策框架 |
| 规费 | 基准 1200/月 | 行业/企业固定收费，不再额外叠百分比 |
| 征管效率 | 初期 1.0 | 之后行政/腐败可调整 0.80—1.00，须有系统依据 |

- **税基：** 所得＝工资＋已收股息＋净房产收益；企业只对正利润；房产税由持有者付，不同时向租户企业和业主扣。税负会反向影响投资、可支配收入、需求与后续税基。
- **支出：** 公共工资、采购/维护、救济、利息、已实际支付资本建设；房产出售另列资本性收入。未付款义务与实际支出分开。
- **预测：** 常规预算不把尚未成交的房款当稳定税收；贷款不入财政收入，偿还本金不入财政费用，二者进入融资现金流。
- **等式：** `财政结余＝实际财政收入−实际财政支出`；`现金变化＝结余＋借款本金−偿还本金`；`债务变化＝新借−还本`。科目明细包括公共租金/市政售房等当前真实业务，基准这些额外科目为 0。
- **中央/教会：** 基准外部拨款 2500，教会捐赠 660，必须扣对手账户。官方传教扶持或住房补贴须有收款人。
- **公营企业：** 独立运营钱包、采购、工资、盈亏；只将净上缴列市政收入，不把其营业额再完整当财政收益。
- **界面/验收：** 收入/费用/资本/融资四类可追溯、显示实际/预测；参考 28817−28300＝517；税率冷却与幅度实际生效；高税率不能无限保证钱更多。

## M10 贷款、银行、信用与危机

**阶段/来源：** P05 简单政府贷，P09 深化；G Q53—55、E §1/7.3/9/14。

- **早期：** 外部贷款人真实向市政放款；基准政府本金 60000、月息 1%、剩余 12 月宽限，只付息 600，宽限期无本金偿还。到期与之后摊还月数必须来自显式配置，不从宽限期推断。
- **额度：** 建议新借款上限＝过去 12 月平均月税收×6；不足 12 月历史用当前税基估计。已有债务/偿债压力还需审核，不只看现金。
- **完整三类：** 政府贷款、家庭按揭、企业贷款分别有借款人与合同；后两者可聚合，不能把所有本金挂市政账。
- **银行：** 国有政策支持、私人银行进入和差异条款在 P09。市内银行用真实可放资金付款，居民存款是资产/银行负债，不能把存款镜像和银行现金重复当全城现金；若未来做货币创造需另立明示模型，V1 守恒版不隐式加入。
- **信用：** 税收稳定、净现金、债务、偿债记录、资产和成长共同决定信用；银行额度/利率随信用变化，信用不是治理最终分数。
- **违约：** 钱不足先记欠息/欠本、协商展期/处置/支援；不能无限负钱包。住房滞销、需求衰退与信用收紧有变量来源和预警，不按固定年突然扣钱。
- **界面/验收：** 利率以月/年明确标注，不混用；放款增加现金和负债但不加利润/GVA；还本改变本金，利息改费用；借贷双方对应，额度与宽限、第 13 月/到期均验证；融资/拆房无无限现金。

- **主要页面：** 城市总览/地图、规划与双路径报价、住宅产权/租赁、企业/市场、公共预算/税政/债务、库存/贸易、学校/防御/宗教政策；后期科技、人物档案、国家与评价。
- **数值口径：** 月份、币种/单位、来源、存量/流量、实际/预测同时明确；营业额≠利润≠现金变化≠GVA。居民人均税前/可支配收入与劳动者平均工资单列。
- **交易诊断：** 用户能展开为何停工、缺客流、无原料、岗位不足、欠薪/欠租、税基下降、报价无人承接；不用只有“繁荣指数”的黑箱替代。
- **建造 UX：** 免费规划、边界/入口红绿反馈、R 旋转、平移缩放；两种方案并排比较市政/私人出资、时间、品质与长期维护。确认/取消与账目一致，规划不是强制任务。
- **响应式：** 桌面、手机、平板均能访问管理面板；移动端选择工具回到地图。装饰层不拦输入，低亮/低分辨率仍可读；尊重减少动态效果设置。
- **接口：** 保留 `/api/state`、`/api/placement`、`/api/commands` 的适配入口，逐阶段新增 `request_quote / accept_quote / zone_plot / set_policy / apply_loan / sign_trade_contract` 等意图；新增权限、状态版本和重放防护，不伪装成已有命令。
- **验收：** 真实点击/键盘/触摸完成任务并核对后台；显示页面或截图不算业务通过，网络失败/忙碌/非法命令可理解，旧按钮不能调用不存在功能。

## M21 存档、迁移与配置兼容

**阶段/来源：** P01 起、P08 完整；G §12/14、E §10/12。

- **保存：** 原子写入、备份、版本/配置指纹；保存实际生成地图、建筑/产权/租赁、账户余额与未清义务、企业/就业合同、库存/在途、报价样本/投资合同、政策冷却、教育队列、人物/事件与 RNG 状态。
- **一致性：** 读取不重新生成开局、不重抽报价、不重发工资或交易；未提交月不得作为成功月保存。连续运行与保存再运行结果一致。
- **校验：** 配置单位、IDs、人口/岗位/住房、交易幂等与账目、库存/货单、贷款本金、产权份额、报价约束一并检查；错误保留当前世界。
- **旧档：** 已有版本 1→2 的原型迁移继续按历史范围说明；升级到守恒模型不能凭旧政府单边账反造所有历史雇主/房东凭证。
- **货币：** 旧银镑与新 CR 必须保存单位。没有用户认可的映射不静默等值换币；可保留旧档查看/导出并新开 CR 场景。若允许继续旧城，期初重分类/资金来源桥接与转换范围单独审查，不能把桥接假装本月营业额。
- **维护约束：** 未来扩展只进入一个权威新经济核心，不长期维护两套同时增长的经济系统；旧版解析适配、历史文件和对照 fixture 保留，不覆盖原档。
- **界面/验收：** 读档前提示模型/单位/兼容结果；损坏或未知版本拒绝且可恢复原城；备份真实可读，报价/债务/欠付/冷却/随机恢复全部一致。

## M24 经济触发器：市长下台与游戏结束

**阶段/来源：** P11（新增）；G Q7/9/45/§8.2/§9.4，U 2026-10-16 决定。完整提案见 [游戏最终设计要点与校长修正-2026-10-16 §3](../游戏最终设计要点与校长修正-2026-10-16.md)。

### 触发位置

`industry_economy.advance()` 月结流程的**月初**（即 `make_report` 之后、`last_report = report` 之前或之后），由独立触发器读取月报判定。**触发器只读不写**——不修改经济状态、不重算月结、不写假付款。

### 触发项（设计草案，实施前需作者复核）

每项"极度异常"指**单项持续多月显著超出经营常识的边界**：

| 项目 | 默认严重条件（提案）| 持续窗口 |
|---|---|---|
| 失业率 | ≥ 70% | 连续 6 月 |
| 政府现金 | ≤ -50,000 CR | 连续 6 月 |
| 累计未偿工资 | ≥ 当期应付工资 × 3 倍 | 连续 6 月 |
| 月营业额 | ≤ 50 CR | 连续 6 月 |
| 人口净变化 | 总居民下降 ≥ 50% | 从开局累计 |

### 触发与宽限

- 首次进入"新加入"项触发 **N 个月宽限期**（建议 6 月）：玩家收到"经营预警"通知，月报顶部增加醒目警告；
- 宽限期内玩家可选择应对（补库、补贴、限招、限裁、迁居、求援中央等）；
- 宽限期结束仍触发 → 触发"市长下台"事件链：
  - 议会（NPC 利益代表团）对市长评价度下降；
  - 季度议会触发"不信任案"或"经济紧急状态"提案；
  - 议会表决通过 → 市长下台；
  - 玩家城市进入 **game_over** 状态，所有命令被拒，但可读存档/查看历史。

### 多项叠加规则

- 单项触发：进入宽限期；
- **多项（≥ 2 项）同时触发：不进入宽限期，直接触发市长下台事件链**；
- 这避免给玩家"必须多项失败才算失败"的逃课空间。

### 收尾画面

- "任期回顾"界面：列出玩家取得的全部成就（建了多少建筑、养活了多少就业、修了多少次事件等），不评价输赢；
- 历史与档案可保留可导出，但不再继续推进；
- 玩家可主动"重新开局"或退出。

### 边界

- **经济崩溃首先判定为玩家责任**：经济内核不主动调整参数救场；触发器只观察，不修改；
- 触发器接入位置应保证：若关闭触发器，城市仍按现有规则月结，不影响守恒与运算；
- 阈值与宽限期必须外置为可配置（建议 `data/governance_triggers.json`），不写死在代码里。

### 与既有 M18 的关系

- M18 国家、议会与条件事件是触发器下游（议会对市长的评价、提案、不信任案）；
- M24 只负责"经济是否触发事件链"，**政治事件的细节仍由 M18 实现**；
- 提案、不信任案需议会代表团存在——M24 实施时应校验 M18 议会是否可用，未到位前以"中央直接委派结果"过渡。

### 验收

- 月初报告读取独立、判定与经济结算解耦；
- 关闭触发器，经济模型保持守恒；
- 单项触发进入宽限期，多项同时触发直接下台；
- 玩家可收到预警通知，并在任期内采取行动；
- 触发后游戏进入不可重置的不操作状态，存档保留；
- 阈值变更通过配置实现，不改代码。
