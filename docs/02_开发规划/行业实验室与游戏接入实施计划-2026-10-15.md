# 行业实验室与游戏接入实施计划

日期：2026-10-15。依据：用户批准的行业双指标V1.0，以及本轮“先GUI模拟、再接游戏”的授权。

## 目标与边界

提供可实际操作的中文桌面实验室：实时调参、基准对照、七行业指标、趋势、方案保存载入、报告导出；共用行业模型与可审计现金/产出月度实验引擎。游戏经济入口使用同一引擎连续推进并支持存读档。

这次接入的是行业经济运行与操作界面，保留现有地图资源与旧实现；不声称完成外交、跨城迁移、17类商品运输、完整建筑建设和全部V2.1验收。实验使用明确标记的标准交付单位，并显示真实运行范围。

## 模块树

```text
data/economy_v2/industry_labor.json：唯一生效的双指标配置
data/economy_v2/industry_lab.json：场景、交易预算、界面参数元数据
backend/systems/v21/industry_model.py：从已验证参考提升的唯一公式实现
backend/systems/v21/industry_economy.py：有限账户、库存与劳动力连续状态
├─ industry_settle.py：真实收付款、消费、采购、税费、股息
└─ industry_scenario.py：参数校验、初始状态与报告/持久化
tools/economy_lab.py：桌面GUI；后台单工作线程模拟，主线程绘图
backend/industry_api.py：游戏状态、参数操作、月推进和存读档
frontend/industry.html：游戏行业经营界面
backend/app.py：恢复可启动入口，接行业API和经营界面
```

## 执行顺序

1. 写测试，先确认新运行入口缺失；提升模型且让旧参考入口转发，禁止复制两套公式。
2. 用配置和已有七行业/钱包构建场景；加入X群体就业分布，所有资金使用整数分，外部买方有有限现金。
3. 接通工资、投入、产出、有限预算购买、税费和每月现金/库存/劳动力断言，测试真实参数干预。
4. 实现中文GUI，沿用V1交互但不依赖已封存V1模块；自动重算防抖，过期结果不覆盖新结果。
5. 真正启动GUI、调整参数、检查表格和曲线、保存/载入/导出，取得界面和数据证据。
6. 游戏API与界面调用同一运行类；推进、政策变更和存读档均原子更新，回归桌面同参数结果。
7. 更新启动脚本、README、文档导航、规范状态与更新日志，交付验证记录。

## 关键验收

- 运行 `python -m pytest tests/v21/test_industry_runtime.py -q`，至少验证资金、劳动力、输入产出、干预、参数校验、状态恢复和API同源。
- 运行 `python -m tools.model_design.validate_industry_labor`，原33项模型验证继续通过。
- 运行 `python -m pytest tests/v21 -q`，记录确切通过数，不能用通过数量代替经济验收。
- GUI必须实际运行和操作，不能只import成功；曲线及指标对参数真实响应。
- 120月运行只作为本次标准交付包实验场景检查；不冒称五城完整世界已稳定。

## 线程与状态边界

桌面仅一个后台计算线程，输入为独立配置副本，输出为不可共享修改的报告；Tk控件只在主线程更新。主线程合并快速调参，丢弃旧版本结果，关闭窗口停止提交任务。游戏使用请求锁；所有推进先在状态副本执行，断言通过后替换当前状态。GUI试算不能修改游戏存档或运行状态。
