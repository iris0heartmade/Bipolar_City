## 1. 范围与调用关系

对照依据：`docs/01_原始输入/Bipole_城市经济系统开发输入_V1.0.txt`、`docs/03_设计规范/游戏模块开发要求与详细设计.md`、居民分群配置。实现入口如下，均为组合调用关系：

```text
tools/economy_lab.py：图形调参、保存方案、展示最后一个月
└─ EconomySimulation：每次调参重新从初始状态推演
   ├─ EconomyParameters：配置、范围与人口约束校验
   ├─ model_engine：装配行业、居民群体、战略资源
   ├─ model_sim：预算 → 订单 → 收付 → 更新状态 → 月报
   └─ 自有 Ledger：企业、家庭、政府、教会、外部五个账户

游戏/参考城另有 core/settlement.py 统一清算体系
└─ 实验室未调用这套清算体系
```

实验室在界面线程内同步运行有限月循环，没有后台模拟线程或进程。`refresh()` 每次新建演化器，通常跑120个月，仪表盘显示最后一个月，不是政策从当前城市状态生效后的续跑。

## 2. 结论与实测

工具已具备参数操作、收入滞后预算、非负余额、慢速信仰变化和曲线输出的基础。但存在会改变经济结论的实现错误，尚不能作为完整模型合理性验收依据。守恒（通俗比喻：钱在钱包之间搬动时总数对得上）不等于报表和经济行为正确。

以下金额单位均为 CR，实际计算金额除以100展示。

| 默认首月项目 | 经济输入基准 | 实测 |
|---|---:|---:|
| 企业营业额 | 340000 | 344836.14 |
| 企业税前利润 | 42400 | 46733.54 |
| 财政结余 | 517 | 月报1178.47，政府现金实际增1036.98 |
| 家庭现金增加 | 8431 | 6698.27 |
| 全城现金增加 | 27100 | 24600 |
| 企业工资 | 121900 | 121900 |
| 公共工资 | 14400 | 14400 |
| 就业/失业 | 1500/150 | 1500/149 |

默认120个月可执行且现金残差为0；私企工资总额从首月121900降至第120月8183.40，人口一直3000、就业一直1500、企业数量一直86。该结果有工资公式的明确结构性原因，不能解释为经过验证的自然经济演化。

## 3. 关键问题

### 3.1 严重：订单金额被当成实际成交收入

位置：`model_sim.py:459`、`:475`、`:510`、`:589`。

`_realised_revenue` 先按供给分配后的订单算收入，随后 `Ledger.pay()` 按余额截断。调用者没有使用其返回的实付金额重算营业额、工资收入、利润、分红和下期预算。

复现：新建模拟器，将企业、政府、家庭账余额与各群体现金置零后推进一月。月报企业营业额180698.67，四类真实销售入账合计93200；月报居民毛收入152848.88，工资、公共工资、股息、商业租金实际入账合计93200，另有住宅内部租金口径。资金缺口151848.91，现金残差仍为0。

另有中间品和私人资本品订单进入销售统计，但没有对应交易、资产变化和行业成本配对；企业合并账户下内部购销净现金为0可以简化，但仍须记录购销双方及资本支出，否则无法复核利润与现金桥接。

### 3.2 严重：战略贸易重复计入，库存与支付脱节

位置：`model_sim.py:489`、`:624–647`；经济输入§8.2明确资源贸易包含在总贸易中。

总进口68000、出口88200已经包括粮食/魔材进口5500及煤/钢出口3000，资源模块又额外付款和收款。默认净现金增加因此恰好少2500：27100−5500+3000=24600。

资源进口无条件补缺口，即使付款被截断仍把完整进口数量加进库存；出口也未先按可出售库存限制。开工用量由产能份额与上期就绪度驱动，不是当期实际生产和订单。默认资源库存合计首月1426.747、第120月76600.842；该合计混用了吨与箱，不能作为有明确实物单位的总库存。

### 3.3 严重：亏损被抹为零，企业风险指标失真

位置：`model_sim.py:600`、`model_engine.py:180`。

税前利润被 `max(0, ...)` 截断。正确要求是利润可为负、仅应税利润和可分红利润不低于零。复现零营业额时，仍有121900工资成本，六行业税前利润却全为0。

行业 `cash_cents` 未随总企业账更新：120个月后行业现金合计仍12000，企业主账3572489.66。因此现金续航和行业风险展示不是实际余额。企业数没有进入退出流程；长期亏损无法形成完整破产反馈。

### 3.4 严重：迁徙与岗位变化没有维护人口身份

位置：`model_engine.py:230`、`model_sim.py:735–820`。

初始化按比例取整失业者，未补残差，默认150变149。迁徙只改群体人口，不改就业、失业和家庭户数；岗位缩减也没有同步裁员。住房设400套，推演120个月后：人口1600、就业1500、失业149、家庭750户，劳动力人数已超过全城人口，住房空置指标仍只显示0。

招聘 `int(unemployed*0.25)` 使剩1–3名失业者时无法录用。产能劳动力用全体劳动力而非实际匹配上岗者，进一步掩盖缺岗问题。

### 3.5 高：工资目标公式造成长期机械下跌

位置：`model_sim.py:683–699`；对照经济输入§4.6。

设计目标以基准工资为锚，包含物价、相对基准技能岗位紧张度、信仰容忍与最低工资。实现是“当前工资×全城岗位/劳动力”，默认1500/1649始终小于1，所以工资每月重新向更低目标调整。没有基准紧张度归一化，没有最低工资约束，没有价格指数反馈。默认私企工资120个月下降至首月的约6.7%，并非单纯调参结果。

### 3.6 高：收入层被平均化，贫困与储蓄为占位值

位置：`model_engine.py:219–236`、`model_sim.py:515–518`、`:878–879`。

设计与居民配置区分低中高收入、资产份额、救济份额、税负与消费篮子。实现把工资和资产收入按人口分配，首月三群体人均毛收入均约58.3566 CR；财富再按人口重分配，群体的人均收入差异消失。消费篮子、房产税份额、救济份额没有参与实际订单和分配。贫困率、储蓄率固定0，不能用于判断居民健康。

### 3.7 高：月报混用结算前后状态

位置：`model_sim.py:702–725`、`:825–947`。

收付之后先调整工资、信仰、人口，再重算部分税费、捐款与月报。首月教会实际给市政660，月报按更新后的信仰相当于659.64；收税时居民毛收入尚未更新，而月报按更新后收入重新算个税，导致首月财政月报与现金变化不同。缺钱场景还把应付公共工资、救济等当作实付收入；救济超过毛收入时，可支配收入又被毛收入上限截掉。

平均就业工资仅统计私企工资却除以含公共雇员的就业人数；房地产增加值少了商业租金收入。债务余额一直是初始债务，信用利差只展示、没有反馈实际利息付款。残差仅返回数字，没有在引擎内执行断言。

### 3.8 中：参数表覆盖不等于行为覆盖

对101项参数进行单项边界调整、每次跑24个月并比较所有月报字段：38项产生变化，59项字段完全相同，4项因人口恒等式拒绝单独修改。59项包含4项界面锁定的结构参数，其中每年月份的边界值与默认相同。因此其余55项只能称为“本次场景未观察到响应”，不能直接称为55项全无效：迁徙、工资上限等需要触发条件。

代码核实未接入的典型项：商户价格选择系数、价格调整、教育完成/技能转换/训练周期、最低工资、企业进入与退出条件、进口出口价格指数、贷款本金宽限期和摊还期。教育每教师席位翻倍仅改变学校覆盖率，未改变24个月任何其他指标。

道路、通勤与物流、住房开发、贷款本金偿还、自然增长、教育培养、完整企业退出尚未进入这条演化路径。服务因子默认为1属于设计允许的早期简化；未接入功能应标为暂未实现，不能拿相关滑块的曲线无变化判断政策无效。

## 4. 设计覆盖与修复顺序

| 层级 | 状态 | 风险 | 建议下一步 |
|---|---|---|---|
| 工具操作与外置参数 | 已有基础 | 参数可调但未必生效 | 标出已接入/条件触发/待实现 |
| 单城经济核算 | 存在严重偏差 | 守恒曲线掩盖假收入和重复贸易 | 统一实际交易来源，首月逐分对账 |
| 就业、迁徙、分群 | 部分实现且身份失配 | 会把不可能的人口结构当趋势 | 每月校验身份与岗位、同步户数 |
| 工资和利润演化 | 与设计公式明显不同 | 默认工资坍缩、亏损不可见 | 恢复基准锚、负利润和实际行业余额 |
| 价格、教育、企业退出、贷款 | 多项未接入 | 无法评估政策长期合理性 | 逐模块接入后做因果场景测试 |
| 空间与开发 | 未进入实验室模型 | 无法判断道路和地产政策 | 作为后续阶段，明确实验范围 |

建议先修真实收付、贸易与月报，再修身份和工资，再做企业/教育/价格等反馈。不建议先继续扩大参数数量。可以复用现有统一清算体系；`model_engine` 顶部“与参考城共享 core/settlement.py”的说明与实际依赖不符。

## 5. 验证边界

- 执行 `python -m pytest -q`：387项通过，耗时2.66秒。
- 实际执行默认首月、120个月、账户无现金、住房约束、零销售亏损及参数响应实验。
- 首月销售测试允许相对误差5%，人口失业测试允许绝对误差0.005，部分许可费测试只检查报表字段；不能替代逐笔交易、身份和现金桥接验收。
- 本次不声称验证图形界面的实际鼠标操作，不修改经济代码，也没有把独立实验室的结果当作游戏运行时验收。
- 本报告的“基准”指经济输入V1.0。分群与长周期演化允许不同，但差异必须有显式模型说明与可复核交易，不能静默放宽基准测试。
