## 1. 设计边界

已确认：Web 展示、JS/Python、后端优先、整数格子、已有城镇开局、固定模板与可复现种子、最小垂直切片（通俗比喻：先做一条完整可玩的流程）。

首个目标：放置住宅 → 确认预算 → 施工 → 竣工 → 人口迁入 → 财政反馈 → 保存与恢复。

技术建议尚未锁定：Python 模拟核心 + FastAPI 通信层 + 原生 JavaScript/Canvas 展示 + 版本化 JSON 存档。框架和依赖在实施前核实；无需现在引入 React、多人同步或数据库。另一条可选路线是全 JavaScript 后端，可减少语言切换，但偏离稿件推荐的 Python 模拟路线。

地图尺寸、初始住宅数、费用、税率、施工时长与迁入速度全部使用外部配置；示例数值不是正史或已确认平衡参数。

## 2. 模块与调用关系

以下是组合与调用关系，不使用多层类继承：

```text
游戏
├─ Web 展示与操作
│  ├─ 等距地图、选格、旋转、镜头
│  └─ 建造工具、人口/财政面板、保存恢复
│        ↓ 提交操作意图，读取状态
├─ 后端命令入口（通俗比喻：统一办事窗口）
│  ├─ 建造校验 → 蓝图与施工 → 财政记账
│  ├─ 世界时钟 → 施工更新 → 月度人口 → 月度财政
│  └─ 存读档 → 状态校验 → 恢复世界
├─ 世界状态（通俗比喻：唯一有效的城市账本）
│  └─ 时间、地图、建筑、人口、现金、种子及版本
└─ 静态配置与测试
   └─ 地形模板、建筑定义、平衡参数、回归用例
```

M0 使用单进程、单一模拟更新入口。前端绘制循环只显示状态；后端推进一次时间，才更新施工和经济。暂停时不推进模拟；加载前停止推进，成功恢复后按存档暂停状态运行。命令与时间更新串行执行，避免重复扣款；不引入多进程或嵌套模拟循环。

## 4. 验收与风险

| 验收场景 | 必须观察的结果 |
|---|---|
| 合法住宅建设 | 确认时扣款一次；时间推进施工；竣工增加容量；后续月度迁入并反映收入 |
| 非法位置/资金不足 | 有可读原因；现金、建筑和施工队列保持原状 |
| 重复提交/暂停 | 无重复扣款与容量；暂停期间时间及施工不变化 |
| 保存→加载→继续 | 时间、人口、现金、朝向、施工状态一致；与连续运行结果一致 |
| 120 月后台模拟 | 无重叠建筑、超容量人口或账目不守恒；无浏览器也可完成 |
| 浏览器操作 | 实际执行点击、旋转、建造、推进、保存与加载；同时核对后台状态 |

| 风险 | 处理方式 | 下一步 |
|---|---|---|
| 用推荐参数误当定案 | 配置标记为 M0 测试参数 | T01 明确默认值 |
| 简化财政与私人住宅设计矛盾 | M0 仅验建设、税收和维护；销售/租赁留给 M1，清楚标注简化范围 | T01 定义产权与记账边界 |
| 画面先行导致模拟不可测 | 先验证纯后端，再接最小 Web 操作 | T02—T08 |
| 世界观名词缺少原作依据 | 使用测试城市/占位建筑，不编造议席和正史角色 | 后续接入世界书 |
| 时间推进与命令竞争 | 单一更新入口、串行命令、幂等确认（通俗比喻：重复按确认只办一次） | T05、T08 |

## 5. 后续里程碑

2026-10-13：M1 的住房销售、公房租赁、实际入住、消费约束的集市商户、岗位与财政闭环已实现。新增魔导工业 UI 和已知原版存档迁移。本轮细节见《验收记录-0.2.0.md》；工坊产出、产业库存和住房按揭仍分别归后续产业/M2。

| 阶段 | 范围 | 进入条件 |
|---|---|---|
| M1 | 已落实政府建房出售、待售资产、公共住房、就业与集市商户；产业生产后续深化 | M0 全部验收通过 |
| M2 | 政府贷款、居民按揭、企业融资、信用及可恢复风险 | 产权与财政账目稳定 |
| M3 | 5—8 个 NPC 城市、供需贸易、战略库存与运输容量 | 本地经济可解释且稳定 |
| M4 | 三科技树、教育、核心人物及技术扩散 | 城市与国家时间推进稳定 |
| M5 | 议会、条件事件、政治评价、交通深化与 20 年评价 | 前述系统可独立验收 |

后续阶段分别细化，不在 M0 同时实现。不得恢复领土征服、Godot 或全人口通勤模拟。
