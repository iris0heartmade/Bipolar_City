## 2. 真实浏览器检查

`python -m scripts.browser_check`：**12 条检查通过**，JavaScript 页面异常列表为空。使用独立 Chromium、独立服务及临时存档，鼠标/键盘/触摸均经过真实输入接口；没有通过写入世界状态代替游戏操作。

| 场景 | 实际观察 |
|---|---|
| 原建造闭环 | 旋转公寓、河流非法放置拒绝、蓝图免费、批准扣 7,800、实际日施工、暂停与月推进 |
| 公寓产权 | 未售公共公寓改为待售后容量从 336 降至 280，居民已有替代私人住房 |
| 实际成交 | 首月售 2 户、收到 2,000 银镑，库存从 14 减到 12，容量从 280 增至 288 |
| 会计显示 | 月报包含实际房款，账本单列成交，经营面板显示成交与库存；已售住房不能切回公房 |
| 岗位约束 | 人口在 305 岗位处停止增长；实际扩建工坊后增加岗位并继续迁入 |
| 公房租金 | 居民进入新增公共住宅后产生租金；不是建成就默认满住或自动收租 |
| 集市 | 商户逐步入驻到 5/5，实际岗位、地方税和铺位租金有效 |
| M1 存读档 | 保存后继续经营再读取，产权、已售户数、入住、居民余款、商户和全部账目逐字段一致 |
| 桌面 | 1440×1000 魔导 UI 无横向溢出，视图、详情、分类、指南均可用 |
| 手机 | 390×844 无横向溢出，触摸放置/取消、开发方案选择与经营面板可用 |
| 平板 | 800×900 无横向溢出，经营面板可滚动访问 |

最初公房场景在 9 月后未入住。后台复现确认当时人口/岗位均为 305，私人住房仍有余量；随后在浏览器真实新增工坊，验证增加岗位后公房入住与租金，而没有修改人口或绕过经济约束。
