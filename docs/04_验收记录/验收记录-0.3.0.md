| 类型 | 内容 |
|---|---|
| 配置 | `data/economy/reference_city_v1.json`、`input_output_v1.json`、`calibration_overrides.json` |

`core/simulation.py` 的日/月时钟，也未替换 `systems/finance.py`。本版本交付的是
**可校验、可复用、已被测试覆盖的经济基础设施**，不是已完成的资金守恒版游戏。

## 3. 配置自洽验证

`tests/economy/test_reference_config.py` 的 26 项测试**全部由原始参数重算**，
不从配置的派生字段读回再断言自己：

- 六行业逐行业重算税前利润，得到 5700/10100/13800/5340/4160/3300，合计 42400。
- 私企工资 240×65 + 400×95 + 210×110 + 280×82 + 130×88 + 120×90 = 121900。
- 私企雇员 1380 + 公共雇员 120 = 就业 1500，与人口恒等式 1500+150+1350=3000 闭合。
- 营业额八来源逐项相加等于 340000；企业投入 86000 + 68000 = 154000。
- 税收由税基重算：173300×0.08 = 13864；5000000×0.0012×(1−0.15×0.55) = 5505。
- 战略库存四项满足 期初+月产+进口−月用−出口 = 期末。
- 公共岗位 120 人、工资 14400；公共采购七项合计 8600；学校 30×24=720 席覆盖 900 学龄人口 80%。
- 住房 600+150+50 = 800 套；600×47 = 28200。
- 救济 3200 是由市政结余 517 反推的唯一解，已登记为 A-03。

**配置卫生检查**：六行业配置中不存在 `profit`、`net` 等派生字段；市政配置中不存在
`s`、`gva`。派生值只存在于 `derived_targets`，且注明"引擎必须自行计算，禁止回写配置"。

`tests/economy/test_reference_month_settlement.py` 把 `input_output_v1.json` 的每条
流向翻译成 24 笔真实交易（付款方与收款方都显式指定），跑过清算引擎并核对结果：

| 主体 | 实测现金变化 | 文档目标 |
|---|---:|---:|
| 企业 | +17312 | +17312 |
| 居民（家庭主钱包 + 房东） | +8431 | +8431 |
| 市政 | +517 | +517 |
| 教会 | +840 | +840 |
| **本地合计** | **+27100** | **+27100** |
| 外部（世界其余部分镜像） | −27100 | −27100 |
| **全世界** | **0** | **0** |

守恒检查返回 `violations = []`。测试同时确认：

- 企业间互购 86000 记为企业付给企业自己，现金净影响为 0，不重复计入营业额。
- 私人资本投入 15000 与资本品采购 15000 等额进出，净对外流量公式因此不出现这两项。
- 粮食 4500 + 魔材 1000 的战略品进口金额已含在 68000 内，没有第二笔付款。
- 防御/魔法材料 1100 已含在公共采购 8600 内，没有重复计费。
- 房东作为家庭财产身份收到住宅租金 28200 与商业租金 9500、付出维修 16700，
  家庭主钱包不被重复入账。

## 6. 开发过程中发现并修复的缺陷

以下问题由测试发现，不是预防性猜测：

1. **预留支付后没有自动核销。** 支付一笔有预留的交易后，预留额度仍然挂账，
   导致部分履约无法释放剩余部分。改为按 `source_ref` 归集预留、清算时自动核销。
2. **读档后无法恢复幂等。** `Settlement` 不接收已结算流水，重开服务后重发同一笔
   工资义务会二次付款。新增 `settled` 构造参数，读档时载入已清交易。
3. **房东子账户导致家庭现金漏出合计。** 原实现把有子账户的父账户排除在现金合计外，
   使 households 的 157131 CR 凭空消失、守恒检查报错。修正为：所有账户都是独立现金
   钱包，`parent_account_id` 只声明财产身份归属，并新增 `mirrored_pairs()` 诊断重复记账。
4. **带 BOM 的配置文件直接崩溃。** Windows 编辑器保存的 JSON 带 BOM，
   `json.loads` 抛 `JSONDecodeError`。`read_json` 改用 `utf-8-sig`。

另有两处属于测试自身写错，已更正：商业租金与维修均为本城内部转账，
全城现金净变化应为 0 而非 −7200；交易类别汇总是付款方视角的支出额，不是类别净流量。

<a id="limits"></a>
## 7. 未完成边界

- **玩家可见行为未变。** 居民收入仍按人口自动增加，新引擎未接入日/月时钟。
- **未接线。** `systems/finance.py` 的市政单边 `record()` 仍在服役，尚未改为由统一交易推导。
- **余额不足策略未实现。** 目前是整批拒绝；缩量、欠薪、欠租与义务取消流程待做。
- **未清义务与模型版本未持久化。** 期初/期末余额已可存档往返一致。
- **GVA 支出法未验证。** 生产法组成（私企 176500 + 房产 21000 + 政府 14400）已核对，
  支出法的等价展开尚未在引擎中实现，登记为 A-07。
- **行业×行业交易矩阵缺失。** 原始输入只给互购总额，未给分配矩阵，登记为 A-06，
  须在 P05 逐店拆分前补齐。
- **技能结构与家庭收入分层缺失。** 原始输入未给，登记为 A-05，P03 消费篮子依赖此项。
- 本记录只覆盖后台纯逻辑。**没有做浏览器端验证**，因为本阶段没有新增界面；
  下一阶段接入 Web 页面时必须真实点击验收，不能以页面出现代替功能完成。
