## 3. 规则来源与优先级

1. 用户最新明确决定优先。本轮确认：**政府直建与规划住宅地让开发商建设均为玩家选择项，并在用时、花费与建成效果上体现受控随机差异。**
2. 原总纲的明确世界观与玩法决定仍有效：统一议会、不征服占地、自由经营、群体人口、格子化、三条市政/工业/魔法科技树、核心人物不真实衰老。
3. 新经济输入用于细化账户、市场、工资、宗教和校准模型；建议数值不等于已验证的正式平衡。冲突处理见详细设计的 [统一决策表](03_设计规范/游戏模块开发要求与详细设计.md#decisions)。
4. 本轮现行计划和规范将上述内容整合成开发要求。新增的工程细节以“实施约定”标记；未有来源的数值只进入校准配置，不升级为小说正史。
5. 现有代码和历史验收说明已实现范围，不能反向覆盖新要求。原型的 `M0/M1` 与经济输入的 `M0/M1/M2` 含义不同；未来统一使用 **P00—P10**，避免阶段名称冲突。

本轮只交付文档整合与目录整理，不宣称资金守恒新引擎、私人开发商或随机报价已经编码实现。

**进度更新（2026-10-13 第二轮）：** P00 参考场景配置与 P01 账户清算引擎已实现并通过 71 项新测试，
见 [0.3.0 验收](04_验收记录/验收记录-0.3.0.md)。玩家运行游戏时的经营模型仍是旧版，新引擎尚未接入时钟。

## 4. 维护规则

- 原始输入不可静默改写。新输入按文件版本存放，并在统一决策表记录覆盖了哪条旧要求。
- 阶段进度只在主计划维护；模块行为只在详细设计维护，其他文件引用它们，避免复制多套现行规范。
- 每次开发先读取对应阶段和模块；数值变更记录配置版本、单位、原因与实测结果。
- 验收按版本新增到 `04_验收记录/`，记录实际命令、场景、结果和限制。历史失败或旧范围不删除。
- 被取代的实施计划放到 `05_历史方案/`，写明取代关系；旧文件不继续扩展未来排期。
- 图片放到 `06_文档素材/`，使用相对路径链接；目录调整后检查 README 与所有 Markdown 的本地链接。
- CHANGELOG 用中文，最新版本置顶，按新增/变更/废弃/移除/修复/安全分类；没有实测结果不写性能百分比。
